## 요약

- 2026-08-31: DESIGN 작성. Decision Point 11개를 전부 닫아 implement.md가 상속할 미정 항목이 없습니다.
  **실측이 두 결정을 확정했습니다** — `NSHostingController.sizeThatFits`와 `ImageRenderer` 픽셀 probe로 직접 쟀습니다.
  ① macOS `DisclosureGroup`은 펼친 내용에 **들여쓰기를 0pt** 줍니다(라벨 아이콘 시작 12.0pt, 내용 시작 0.0pt).
  지금 하위 행은 부모 앱 이름보다 34pt, 삼각형보다도 12pt 왼쪽에서 시작하고 세 경계 간격은 `0 / 2 / 2pt`입니다.
  들여쓰기를 부모 이름 시작선 **34pt**로, 세 경계를 **4 / 10 / 16pt**로 확정했습니다.
  한 단 더 들이는 46pt 안은 가장 긴 하위 행이 `46 + 231.0 + 8 + 78.0 = 363pt`로 목록 폭 360pt를 넘겨 접었습니다.
  ② 코어 격자는 **열 수를 코어 수에서 두 단계로 유도**하고(`행 수 = ⌈n ÷ 8⌉` → `열 수 = ⌈n ÷ 행 수⌉`) 폭에서 온 값은 열 상한 8 하나뿐입니다.
  14개는 7+7, 10개는 5+5, 24개는 8+8+8이 됩니다.
  열 상한 8의 근거는 `"100%"` 28.0pt에 8열 칸 폭 40.8pt라는 실측이고, 10열은 31.4pt로 여유가 없어 배제했습니다.
  칸은 고정 트랙(18pt) 세로 막대 + 수치 + 코어 번호이고, **수치를 화면에도 둡니다** —
  앞 feature가 카드 폭 232pt에 345pt가 필요해 수치를 뺐던 것과 달리 여기선 자리가 남습니다.
  격자 아래끝은 14코어 **154pt**, 24코어 208pt, **64코어까지 478pt**로 480 안에 들어갑니다(`SPEC §5.4`).
  **`DisclosureGroup`을 유지합니다** — `DashboardDetailExpansionUITests`·`DashboardProcessListDisplayUITests`가
  `AXDisclosureTriangle` 요소와 `triangle.value` 0/1 판정에 매여 있어 자체 조립은 세 회귀 그물을 스스로 걷어냅니다.
  같은 이유로 하위 행을 접근성 요소 하나로 **합치지 않고** 이름 `Text`에만 소속 앱을 담은 이름을 덧붙입니다
  (합치면 `value CONTAINS "PID"` 조회가 깨집니다).
  **값 없음 자리표시는 새로 만들지 않습니다** — 앞 feature가 다섯 번 reject된 자리라 새 표시 요소 8종을 먼저 전수 열거했고,
  전부 `.normal` 분기 안쪽에만 있어 「일부만 빠지는」 조합이 도달 불가능함을 확인했습니다.
  팝업 크기는 상태 분기 밖 `.frame`이 이미 고정합니다(`SPEC §5.5`).
  변경 범위는 표시 계층뿐입니다 — `DashboardView.swift`(`CPUDetailView`·`ApplicationProcessGroupRow`·`CPUCoreUsageGridView` 신설),
  `DashboardPresentation.swift`·`ApplicationRanking.swift`(순수 계산·서식), `DashboardColorPalette.swift`(상수 둘).
  **추정으로 남는 것 셋을 `§근거`에 확인 사실과 분리해 적었습니다** —
  삼각형 폭 12pt는 이 macOS 버전 실측값이라 OS가 바꾸면 정렬이 어긋나고(층 순서는 뒤집히지 않습니다),
  하위 행을 합치면 AX value가 사라진다는 판단은 XCUITest로 확인하지 못했으며,
  스크롤 막대 「항상 표시」 설정으로는 재보지 않았습니다.
