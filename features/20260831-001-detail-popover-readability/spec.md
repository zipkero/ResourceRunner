# 상세 팝업 가독성 명세

## 1. 범위

이미 동작하는 CPU·Memory 상세 팝업 안에서 값을 읽어내기 어려운 두 자리를 다룹니다.
앱 행을 펼쳤을 때 나타나는 하위 프로세스 행의 시각적 구분과, CPU 상세의 논리 코어별 사용률 표현입니다.

수집 계층과 값 계산은 건드리지 않습니다.
표시되는 값 자체는 그대로이고 그 값을 배치하고 그리는 방식만 바뀝니다.

### 입력 맥락

사용자가 실행 중인 앱을 보고 두 가지를 지적했습니다 —
「각 루트 프로그램들을 토글하여 나오는 하위 항목들이 너무 붙어 있는 것 같다」와
「CPU 상세 팝업에 코어도 단순히 텍스트로만 나오고 있어서 UX적으로 별로」입니다.

코드에서 확인된 출발점은 다음 셋입니다.

- `ResourceRunner/DashboardView.swift`의 `ApplicationProcessGroupRow`에서
  `DisclosureGroup`의 하위 행이 `spacing` 없이 `ForEach`로 나열됩니다.
  들여쓰기도, 부모 앱 행과의 시각적 구분도 없습니다.
  간격 문제는 하위 행끼리만이 아니라 **부모 앱 행과 첫 하위 행 사이에도** 있습니다.
  펼친 순간 하위 목록이 부모 행에 그대로 달라붙어 어디부터 하위인지 경계가 보이지 않습니다.
- 같은 파일의 부모 목록은 `spacing: 2`로 이미 촘촘합니다.
  부모 행에는 앱 아이콘이 있고 하위 행에는 없어 두 층의 시작 위치가 어긋나 있습니다.
- 같은 파일 `CPUDetailView`에서 논리 코어별 사용률이
  퍼센트를 쉼표로 이어붙인 `Text` 한 줄로 표시됩니다.
  코어 수만큼 길어지고, 어느 코어가 높은지 훑을 수 없습니다.

`docs/product.md` 「대시보드 — 공통 정보 구조」의 레이아웃 안정성과 「접근성」의 색상 비의존 원칙,
「CPU — 상세 정보」의 논리 코어별 사용률 항목이 관련 요구사항입니다.
`ROADMAP.md` M2(CPU·Memory 핵심 리소스 모니터링)에 속합니다.

앞선 `20260818-001-resource-visualization`에서 카드와 상세의 표시를 개선했고,
그때 상세 팝업 크기를 400×480으로 고정하고 내용은 그 안에서 스크롤하도록 확정했습니다.
이 feature는 그 고정 크기를 전제로 시작합니다.

검토했으나 접은 접근이 하나 있습니다 —
간격과 들여쓰기만 Per-Request로 먼저 손보는 방향은 접었습니다.
코어 표현을 무엇으로 바꾸는지가 같은 팝업의 세로 공간을 나눠 쓰기 때문에,
두 자리를 따로 정하면 고정 높이 안에서 서로 맞지 않을 수 있습니다.

## 2. 목표

상세 팝업을 연 사용자가 두 가지를 눈으로 훑어 알아낼 수 있게 합니다.

첫째, 어떤 하위 프로세스가 어떤 앱에 속하는지를 행의 배치만으로 구분합니다.
지금은 세 경계가 모두 같은 간격이라 층이 보이지 않습니다 —
부모 앱 행과 첫 하위 행 사이, 하위 행끼리, 마지막 하위 행과 다음 앱 행 사이입니다.

둘째, 논리 코어 중 어느 것이 높고 어느 것이 낮은지를 값을 하나씩 읽지 않고 알아냅니다.
지금은 코어 수만큼의 퍼센트 문자열을 순서대로 읽어야만 분포를 알 수 있습니다.

## 3. 제약

- 상세 팝업의 크기는 400×480 고정입니다.
  새 표현이 이 크기를 넘기면 팝업을 키우지 않고 기존 세로 스크롤 안에서 해결합니다.
- 논리 코어별 사용률은 코어 전체가 스크롤 없이 한 화면에 들어오는 배치를 씁니다.
  코어 하나당 한 줄을 쓰는 세로 목록은 이 제약을 만족하지 못합니다 —
  개발 기준 기기가 논리 코어 14개(Apple M3 Max)이고, 14줄이면 CPU 상세의 나머지 내용과 합쳐 스크롤을 넘깁니다.
- 코어별 수치를 Hover에만 두지 않습니다.
  `docs/product.md` 「중요한 분석 정보는 Hover에만 의존하지 않습니다」에 따라,
  화면의 형태와 접근성 이름으로 도달되는 것이 최소선입니다.
- 하위 프로세스 행의 구분은 들여쓰기와 간격으로 합니다(2026-08-31 사용자 결정).
- 레이아웃 안정성을 유지합니다.
  수집 중·정상·실패·중지 사이를 오가도, 코어 수나 하위 프로세스 수가 달라져도
  팝업의 크기와 카드의 위치가 변하지 않습니다.
- 색상만으로 구분하지 않습니다.
  코어 사용률의 높낮이와 하위 행의 소속을 색 외의 수단으로도 알 수 있어야 합니다.
- 새 표시 요소가 접근성 계층에서 이름과 수치로 도달돼야 합니다.
- 코어 수는 기기마다 다르고 실행 중에 알 수 있습니다.
  특정 코어 수를 가정한 고정 배치를 쓰지 않습니다.
- 표시되는 값의 정의와 계산을 바꾸지 않습니다.
  논리 코어별 사용률과 프로세스 값은 지금 쓰는 것을 그대로 씁니다.

## 4. 제외 범위

- 수집 주기·계산·데이터 모델 변경. 표시 계층 안에서 끝냅니다.
- 상세 팝업의 고정 크기 변경.
- CPU 상세의 다른 항목(Load Average, User·System·Idle) 표현 변경.
- 카드(팝업이 아닌 본체)의 표시 변경. 앞선 feature가 다뤘습니다.
- 하위 프로세스 행에 새 정보(스레드 수, 실행 아키텍처 등)를 더하는 것.
  `docs/product.md`가 상세 정보로 열거하지만 이 feature의 범위는 기존 값의 표현입니다.
- 프로세스 종료 같은 조작 기능.
- 코어별 사용률의 이력·그래프. 현재 스냅샷의 표현만 다룹니다.
- 하위 프로세스 행을 구분하기 위한 구분선·배경·테두리(2026-08-31 사용자 결정).
  구분 수단은 들여쓰기와 간격으로 한정합니다.
- 가로 스크롤. 팝업 안의 스크롤은 기존 세로 스크롤 하나뿐입니다.

## 5. 완료 조건

1. 앱 행을 펼치면 부모 앱 행과 첫 하위 행 사이가 벌어져 어디부터 하위인지 알 수 있고,
   마지막 하위 행과 다음 앱 행 사이도 구분되어 다음 앱이 어디서 시작하는지 알 수 있습니다.
   이 세 경계(부모–첫 하위, 하위끼리, 마지막 하위–다음 앱)가 서로 같은 간격으로 보이지 않습니다.
   구분은 들여쓰기와 간격으로 이뤄지며 색에 의존하지 않습니다.
2. 하위 프로세스 행끼리도 서로 붙어 보이지 않고, 한 행의 이름과 값을 눈으로 짚을 수 있습니다.
3. CPU 상세에서 논리 코어별 사용률이 값의 크기를 형태로 비교할 수 있게 표시되어,
   어느 코어가 높고 낮은지를 값을 하나씩 읽지 않고 알 수 있습니다.
   각 코어의 수치는 화면 또는 접근성 이름으로 도달되며, Hover에만 있지 않습니다.
4. 논리 코어 14개인 기기에서 코어 표현 전체가 스크롤 없이 한 화면에 들어오고,
   코어 수가 그보다 적거나 많아도 배치가 코어 수를 따라가며 팝업의 고정 크기를 넘기지 않습니다.
5. 위 표시가 모두 있는 상태에서 수집 중·정상·실패·중지 사이를 오가도
   상세 팝업의 크기와 카드의 위치가 변하지 않습니다.
6. 앱 행을 펼치고 접어도 팝업의 크기가 변하지 않고, 펼친 상태가 목록 갱신 사이에 유지됩니다.
7. 새 표시 요소가 접근성 계층에서 이름과 수치로 도달됩니다 —
   코어별 사용률은 코어 번호와 값이, 하위 프로세스 행은 소속 앱과 값이 읽힙니다.
