# 메뉴바 앱과 모니터링 기반 명세

## 범위

M1은 Dock 아이콘 없이 실행되는 메뉴바 앱, 메뉴바 항목에서 열고 닫는 대시보드 팝오버,
주입 가능한 상태를 접근성으로 구분하는 메뉴바 표현을 제공합니다. 이후 CPU·Memory·Network·Disk Collector가
공통으로 사용할 수집 일정, 최근 샘플 순환 버퍼와 생명주기 제어 기반도 포함합니다.

메뉴바에는 현재 저장소에 있는 정적 아이콘 하나를 표시합니다. 캐릭터 자산 제작과 애니메이션은
실제 CPU 부하 값이 나오는 M2로 미룹니다.

실제 시스템 리소스 값 대신 검증용 상태와 샘플을 주입하여 메뉴바 UI, 생명주기 정책과
모니터링 기반을 독립적으로 실행하고 검증할 수 있는 상태를 M1의 경계로 삼습니다.

  macOS 15 호환은 요구하지 않습니다. 1.0은 Intel Mac을 지원하지 않는 Apple silicon 전용 앱으로 제공합니다.

  `기술 방향` 원칙에 대한 검증된 예외로 분석 문서에 근거와 격리 범위를 남깁니다.
- 사용자 확정: 캐릭터 자산 제작과 애니메이션을 M1에서 빼고 M2로 옮깁니다.
  M1의 메뉴바 표현은 현재 `StatusCatStatic` 아이콘 하나로 고정하고, 상태 구분은 접근성 설명으로만 합니다.

### 확인한 실행 환경 사실

2026-08-06에 macOS 26.5.2 Apple silicon에서 App Sandbox를 적용한 GUI 앱과 적용하지 않은 GUI 앱을
각각 빌드해 직접 관찰한 결과입니다. M1의 생명주기 설계는 이 사실을 전제로 합니다.

- App Sandbox 앱에서도 `CGSessionCopyCurrentDictionary()`가 세션 사전을 반환하고
  `kCGSSessionUserIDKey`를 읽을 수 있습니다. 비Sandbox 앱과 결과가 같습니다.
- 세션 사전의 `CGSSessionScreenIsLocked` 키는 잠금 상태에서만 나타나고 해제 상태에서는 존재하지 않습니다.
  키 부재는 정보 없음이 아니라 잠기지 않은 상태를 뜻합니다.
- `com.apple.screenIsLocked`와 `com.apple.screenIsUnlocked` 알림은 App Sandbox 앱에도 배달되며
  object에 현재 GUI 세션 사용자 ID가 문자열로 실려 옵니다. 세션 사전의 같은 값은 숫자 타입입니다.
- 해제 알림이 도착한 시점에도 세션 사전이 아직 잠김을 보고하는 경우가 실제로 발생합니다.
  사전은 알림보다 늦게 갱신되므로 알림과 사전이 충돌하면 알림을 신뢰해야 합니다.
- `com.apple.screensaver.didstart`와 `com.apple.screensaver.didstop`은 화면 잠금에서 발화하지 않아
  잠금 신호의 대체재가 되지 못합니다.
- `LSUIElement` 앱은 팝오버를 표시해도 활성화되지 않아, 여는 경로에서 앱을 활성화하고 팝오버 창을
  key로 만들지 않으면 `.transient` behavior가 외부 클릭에서 닫을 계기를 얻지 못합니다.
- 메뉴바 상태 항목의 접근성 role은 `Status Menu`입니다. VoiceOver는 이 role에서 접근성 이름을 읽고
  접근성 값은 읽지 않습니다. 접근성 값에만 상태를 담으면 값이 AX 트리에 정상 노출되더라도
  사용자에게 전달되지 않으므로, 상태 구분은 접근성 이름에 담아야 합니다.
  Accessibility Inspector와 XCUITest로 이름·값·role을 각각 확인한 결과입니다.

## 목표

- 사용자가 Dock을 방해받지 않고 메뉴바에서 ResourceRunner의 실행 상태를 확인하고
  대시보드 팝오버를 열고 닫을 수 있게 합니다.
- 실제 Collector 없이도 주입한 부하 상태가 메뉴바 접근성 설명에 반영되는지 반복해서 검증할 수 있게 합니다.
- 이후 Collector가 동일한 규칙으로 샘플을 수집하고 최근 데이터만 유지하도록
  공통 일정·버퍼·생명주기 기반을 마련합니다.
- 후속 마일스톤이 동일한 배포 대상과 검증 환경을 사용하도록 macOS 26.5 이상,
  Apple silicon 전용 지원 정책을 프로젝트에 고정합니다.

## 제약

- 앱과 테스트 대상의 최소 deployment target은 macOS 26.5로 맞추고, 배포 가능한 앱 실행 파일은 arm64만 포함합니다.
- 앱은 메뉴바 전용으로 동작하며 별도 Helper, 관리자 권한, 시스템 확장과
  추가 상주 프로세스를 요구하지 않습니다.
- 메뉴바 항목은 현재 저장소의 `StatusCatStatic` 아이콘 하나만 사용하고 표시 중에 이미지를 바꾸지 않습니다.
- 낮음, 보통, 높음, 매우 높음과 장시간 고부하에 해당하는 표시 상태를
  실제 CPU 임계치가 아닌 검증용 입력으로 주입할 수 있어야 합니다.
- 주입한 표시 상태는 메뉴바 항목의 접근성 이름에 반영되고, 상태가 바뀌어도
  메뉴바 항목의 폭과 기준 위치는 변하지 않아야 합니다.
- M1에서 생성한 샘플과 최근 이력은 메모리에만 유지하며 외부 전송, 영구 저장과
  앱 재시작 후 복원을 하지 않습니다.
- 앱 시작 직후에는 주입된 실제 샘플 구간만 제공하고, 존재하지 않는 과거 데이터를
  현재값으로 채우지 않습니다.
- 팝오버 열림·닫힘, 저전력 모드와 화면 잠금 상태를 수집 일정의 생명주기 입력으로 구분하고,
  상태가 바뀌면 중복 수집 없이 해당 일정 정책을 적용할 수 있어야 합니다.
- 화면 잠금 감지에 사용하는 문서화되지 않은 알림 이름과 세션 키는 macOS 26.5 전용 어댑터 하나에만 두고,
  나머지 계층은 주입 가능한 공개 계약에만 의존합니다.
- 화면 잠금 신호를 해석하지 못하는 상황에서도 메뉴바와 팝오버는 계속 동작해야 합니다.

## 제외 범위

- VoiceOver의 실제 음성 출력 확인. 접근성 이름이 AX 트리에 노출되는 것까지를 M1 범위로 하고,
  음성 확인은 대시보드가 완성되는 M5 접근성 관문에서 핵심 사용자 흐름 전체를 대상으로 수행합니다.
- 캐릭터 콘셉트 확정, 상태별 자산 제작과 메뉴바 애니메이션
- 애니메이션 프레임 일정, FPS 정책과 저전력·화면 잠금에 따른 애니메이션 감속·정지
- 동작 줄이기와 애니메이션 비활성화에 따른 표시 전환
- CPU·Memory·Process·Network·Disk의 실제 시스템 데이터 수집과 실제 값에 따른 상태 판정
- CPU와 Memory의 임계치, 지속 시간, 평활화와 히스테리시스 정책
- CPU·Memory·Network·Disk 카드, 최근 그래프, TOP 5와 상세 지표가 완성된 대시보드
- 사용자 갱신·그래프·애니메이션 설정의 영구 저장, 기본값 복원과 로그인 시 자동 실행
- Intel Mac과 macOS 26.5 미만 환경 지원
- 추가 캐릭터 선택, 장기 이력, 외부 데이터 전송, 별도 상세 창과 사용자 정의 경고
- App Sandbox 최종 정책, 업데이트 전달, 코드 서명, 공증과 설치 가능한 1.0 배포물

## 완료 조건

1. macOS 26.5 이상의 Apple silicon Mac에서 앱을 실행하면 Dock에는 아이콘이 나타나지 않고
   메뉴바 항목이 안정적으로 표시됩니다.
2. 사용자가 메뉴바 항목을 클릭하면 M1 대시보드 팝오버가 열리고, 팝오버 외부를 클릭하면 닫히며,
   이 동작을 반복해도 상태가 어긋나지 않습니다.
3. 낮음, 보통, 높음, 매우 높음과 장시간 고부하 상태를 주입하면 메뉴바 항목의 접근성 이름이
   현재 상태를 포함하도록 바뀌고, 상태가 바뀌어도 메뉴바 항목의 폭과 기준 위치,
   팝오버 열림 상태는 흔들리지 않습니다.
   접근성 이름이 실제로 접근성 클라이언트에 노출되는 것까지 자동 검증으로 확인합니다.
4. 자동 테스트 결과에서 팝오버 열림·닫힘, 저전력 모드와 화면 잠금 상태에 따른
   수집 일정 변경이 확인되고, 일정 변경을 반복해도 중복 수집이
   발생하지 않습니다.
5. 실제 macOS 화면 잠금과 해제에서 수집 일정이 중지하고 재개하며,
   잠금 직후 곧바로 해제하는 짧은 순환에서도 재개를 놓치지 않습니다.
6. 자동 테스트 결과에서 순환 버퍼가 설정한 시간 범위와 실제 수집 주기에 맞는 용량을 사용하고,
   용량 초과 시 가장 오래된 샘플만
   제거하며, 범위 변경이나 앱 시작 직후에 존재하지 않는 과거 샘플을 만들지 않는 것이 확인됩니다.
7. 프로젝트의 앱·테스트 대상은 macOS 26.5를 최소 버전으로 사용하고, 빌드된 앱 실행 파일은 arm64만 포함합니다.
8. M1 디버그 빌드와 관련 자동 테스트가 성공하고, 빌드 산출물에는 ResourceRunner 메인 앱 외의
   Helper나 추가 상주 실행 파일이
   포함되지 않습니다.
