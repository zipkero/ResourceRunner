# 대시보드 시각 언어 재정립

## 1. 범위

대시보드 본체 카드와 두 상세 팝업의 **시각 언어**를 다시 정합니다.
글자 크기 위계, 구역 여백, 선과 면의 사용, 카드와 바탕의 관계, 코어 격자 색 배정, 그래프 판의 보조 표시가 대상입니다.

표시하는 값·항목·정원·계산은 바꾸지 않습니다. 같은 정보를 다른 모양으로 보여주는 작업입니다.

### 입력 맥락

직전 feature `20260906-001-graph-legibility-and-color`가 IMPLEMENT를 닫은 직후,
사용자가 완성된 화면을 보고 「수치가 바뀌면 밀리고 디자인 자체가 90년대 같다」고 지적한 것이 출발점입니다.

방향을 글로 정하지 않고 HTML 시안을 만들어 비교한 뒤 사용자가 세 가지를 골랐습니다.

- 전체 방향은 A안(「차분한 위계」) — 카드 구조를 유지한 채 타입 스케일과 여백을 벌리고 그래프 격자를 걷어내는 쪽입니다.
- 코어 격자 색은 E안(「조용하다 한 번만 튐」) — 75% 미만은 한 톤으로 가라앉히고 75% 이상만 다른 색조로 띄웁니다.
- 라이트 모드 카드 면은 L3안 — 바탕을 시스템 흰색보다 낮추고 카드를 흰색으로 띄웁니다.

시안 파일은 저장소 밖 scratchpad의 `variants.html`·`variant-a.html`·`cores.html`·`light.html`이며,
저장소에 남기지 않으므로 이 문서의 §5가 유일한 기준입니다.

조사에서 확인한 사실:

- 팝오버 바탕으로 쓰는 `NSColor.windowBackgroundColor`는 라이트에서 `#FFFFFF`, 다크에서 `#1E1E1E`입니다.
  라이트 바탕이 이미 순수 흰색이라 **카드를 바탕보다 밝게 만드는 선택지가 없습니다.**
  카드를 띄우려면 바탕을 흰색에서 내려야 합니다.
- 현재 라이트 팔레트에서 가장 밝은 값인 Cached `#ba6e41`는 기존 검증 기준 배경 `#ECECEC`에서 3.11:1로 최소선에 가깝고,
  흰 카드 면 위에서는 3.96:1로 올라갑니다.

검토했으나 접은 접근:

- **B안(데이터 우선)·C안(카드 없는 연속 흐름)** — 카드 상자를 없애는 방향입니다.
  M3에서 카드가 넷으로 늘어날 때 구분이 약해지고, 본체 고정 높이를 크게 다시 잡아야 해서 접었습니다.
- **D안(조밀형)** — 정보 밀도를 높이는 방향입니다. 세로 예산에는 가장 유리하지만 사용자가 A를 택했습니다.
- **코어 색 D안(파랑 → 초록 → 주황 → 빨강 히트맵)** — 변화는 가장 크지만
  네 색이 동시에 눈을 끌어 오히려 바쁜 코어를 찾기 어려웠고, 빨강이 사실과 다른 「위험」을 뜻하게 됩니다.
- **코어 색 B안(파랑 유지 + 대비 확대)** — 기존 설계를 하나도 깨지 않는 선택지였으나,
  사용자가 색조가 갈리는 E를 택했습니다.
- **라이트 L1·L2안(바탕은 흰색 그대로 두고 카드를 회색으로 가라앉힘)** — 시스템 색을 건드리지 않는 선택지였으나,
  L1은 경계가 거의 보이지 않고 L2는 카드가 가라앉아 보여 다크의 「카드가 떠오른다」와 인상이 어긋납니다.

이 feature 착수 직전에 Per-Request로 이미 반영을 끝낸 세 가지가 있습니다.
같은 자리를 다시 만들지 않습니다 — §4에 제외 범위로 둡니다.

### 관련 상위 문서

- `ROADMAP.md` §M2 — 담당 마일스톤입니다. 전환 기준의 「CPU·Memory 카드에서 최근 그래프와 현재 TOP 5를 확인할 수 있습니다」가 계속 성립해야 합니다.
- `ROADMAP.md` §M3 — 「카드 넷이 지원하는 가장 작은 화면에서도 잘리지 않고 모두 도달됩니다」와 본체 배치 구조 변경 의무가 이 feature의 세로 예산 재계산에 걸립니다.
- `docs/product.md` §접근성 — 「색상만으로 정상, 경고와 위험을 구분하지 않아야 합니다」가 코어 격자 색 변경과 맞물립니다.
- `docs/product.md` §공통 정보 구조 — 레이아웃 안정성 원칙이 그대로 유지돼야 합니다.
- `docs/design.md` §대시보드 본체의 세로 예산 — 카드 산술과 `NSPopover` 여백 26pt, 카드 넷 프레임 951pt 계산의 출처입니다.
- `docs/design.md` §접근성 역할과 값 — `.ignore` + `.isStaticText` 관례가 유지돼야 합니다.

## 2. 목표

화면을 훑는 3초 안에 **무엇이 중요한 값이고 무엇이 설명인지**가 크기로 갈리게 합니다.
지금은 값·라벨·머리글이 모두 같은 크기라 위계가 색과 굵기에만 실려 있고, 그래서 표처럼 읽힙니다.

그래프 판에서 보조 표시가 데이터보다 강하지 않게 합니다.
지금은 기준선·세로 눈금·판 테두리·미수집 빗금이 겹쳐 판이 여러 칸으로 갈라져 보이고, 실제 값보다 먼저 눈에 들어옵니다.

코어 격자에서 **바쁜 코어를 찾는 일**이 한 번에 되게 합니다.
지금은 한 색조의 밝기 차이로만 갈려서 88%와 8%가 나란히 있어도 훑어서는 구분되지 않습니다.

라이트와 다크가 한 디자인으로 읽히게 합니다.
두 모드에서 카드와 바탕의 관계가 같은 방향이어야 하며, 한쪽에서만 카드가 가라앉는 인상을 만들지 않습니다.

본체와 상세 두 화면이 같은 시각 언어를 쓰게 해서, M3에서 카드가 넷으로 늘어날 때 적용할 기준을 먼저 세웁니다.

## 3. 제약

표시하는 값·항목·정원·계산식·수집 주기는 바꾸지 않습니다.
순위 정원(카드 5 / 상세 20), 그래프 시간 창 10분, 다운샘플 버킷 규칙, 코어 단계 경계(25 / 50 / 75%)가 그대로입니다.

카드는 라이트·다크 모두에서 바탕 위로 **떠오르는** 방향이어야 합니다.
라이트는 팝오버 바탕을 시스템 흰색보다 낮추고 카드를 흰색으로 두며, 다크는 어두운 바탕 위에 밝은 카드를 둡니다.
그 결과 팝오버 바탕색은 `NSColor.windowBackgroundColor`를 그대로 쓰지 않고 이 feature가 값을 확정합니다.

새로 쓰는 색은 라이트·다크 각각 배경 대비 3:1 이상이어야 합니다.
대비를 재는 배경은 근사값이 아니라 그 색이 실제로 놓이는 면입니다 — 카드 안 요소는 카드 면을, 바탕 위 요소는 바탕을 기준으로 잽니다.
라이트와 다크는 각각 따로 확정하며 한쪽 값에서 반전으로 유도하지 않습니다.

코어 격자의 주황은 **「위험」이 아니라 「지금 일하고 있는 자리」를 뜻합니다.**
정상·경고·위험 세 단계를 가르는 표시는 Memory Pressure가 계속 담당하며, 그쪽은 기호와 라벨로만 구분하고 색을 쓰지 않습니다.
코어 격자에서 색은 세 번째 중복 수단입니다 — 칸마다 정수 퍼센트가 찍히고 막대 높이가 값에 비례하므로,
색을 지워도 어느 코어가 바쁜지는 그대로 읽혀야 합니다.

접근성 도달 범위는 줄지 않습니다.
카드 접근성 이름의 항목, 코어 칸 하나가 접근성 요소 하나인 계약(하위 무시 + 정적 텍스트 + 이름 + 값 + 식별자),
하위 프로세스 행의 소속 앱과 값이 함께 읽히는 것이 모두 유지됩니다.

애니메이션을 도입하지 않습니다. 동작 줄이기·애니메이션 끄기에서 표시가 달라질 여지를 만들지 않습니다.

갱신 주기마다 하는 일이 늘지 않습니다. 새 타이머·새 관찰자·새 이미지 생성·색 보간을 두지 않습니다.

논리 코어 56개가 CPU 상세 첫 화면에 들어오는 현재 상한을 낮추지 않습니다.
코어 칸 크기를 키우려면 이 상한을 지키는 범위 안에서만 키웁니다.

카드 넷을 가정한 M3 세로 예산 계산은 이 feature가 바꾼 카드 높이로 다시 산출합니다.
기준 기기(`visibleFrame` 1084pt)에서 성립해야 하며, 그보다 작은 화면의 해소는 M3가 배치 구조로 맡습니다.

## 4. 제외 범위

아래 셋은 이 feature 착수 직전 Per-Request로 이미 반영됐습니다. 다시 만들거나 되돌리지 않습니다.

- 코어 번호 1-based 표시. 화면과 접근성 이름이 1부터 세고, 접근성 식별자는 배열 첨자(0-based)를 유지합니다.
- 아이콘 정책. 앱 번들 키에만 시스템 아이콘을 묻고, 번들이 아닌 프로세스는 중립 기호 자리로 보냅니다.
- CPU 요약 줄 비율 숫자의 고정 폭. 자릿수가 바뀌어도 뒤따르는 조각이 밀리지 않습니다.

Network·Disk 카드의 색과 배치는 M3가 소유합니다.

본체 배치 구조 변경(세로 스크롤·아코디언·2열)은 M3가 소유합니다.
이 feature는 카드 둘을 한 열로 쌓는 현재 구조를 유지하고 세로 예산 계산만 갱신합니다.

수집·계산·집계 로직, 순위 안정화, 프로세스 식별 규칙은 대상이 아닙니다.

상세 팝업에 새 지표나 새 구역을 더하지 않습니다. 지금 있는 구역을 같은 언어로 다시 그릴 뿐입니다.

메뉴바 항목과 캐릭터 표시는 대상이 아닙니다.

사용자 설정으로 시각 언어를 고르게 하는 것은 M4 소관이며 여기서 다루지 않습니다.

## 5. 완료 조건

1. 대시보드의 글자 역할이 크기로 갈립니다.
   초점 값·본문 값·라벨·머리글 네 역할이 서로 다른 크기를 가지며, 초점 값은 본문 값의 두 배 이상입니다.
   색과 굵기를 지워도 무엇이 중요한 값인지가 크기만으로 읽힙니다.

2. 그래프 판에 가로 기준선이 하나만 남고 세로 눈금이 없습니다.
   판이 여러 칸으로 갈라져 보이지 않으며, 값의 높이를 어림하는 일은 남은 기준선 하나로 계속 됩니다.

3. 아직 수집되지 않은 구간이 자기 경계를 가진 면으로 보이지 않습니다.
   그 구간에 점도 선도 그리지 않아 값 0으로 읽히지 않는 것은 그대로이고,
   아직 수집 중이라는 사실과 얼마나 모였는지는 축 아래 문구로 계속 확인됩니다.
   창이 다 찬 뒤에는 그 자리에 아무 표시도 남지 않습니다.

4. 카드 순위 목록의 머리글이 정원과 제외 규칙을 늘어놓지 않습니다.
   시스템 프로세스가 순위에서 빠진다는 사실은 상세 팝업에서 계속 확인됩니다.

5. 카드 사이의 구분이 선이 아니라 면입니다.
   카드 테두리를 그리지 않고도 어디까지가 한 카드인지 화면에서 갈리며,
   라이트와 다크 모두에서 카드가 바탕보다 떠올라 보입니다 — 한쪽에서만 가라앉는 방향이 되지 않습니다.

6. 구역 사이 여백이 이전보다 넓어집니다.
   카드 안에서 제목 묶음·그래프 묶음·순위 묶음이 서로 다른 덩어리로 읽히며, 여백 단계가 이전보다 위쪽 단계를 실제로 씁니다.

7. 코어 격자에서 75% 이상인 코어가 한눈에 찾아집니다.
   75% 미만 코어는 서로 비슷한 톤으로 가라앉고, 75% 이상 코어만 다른 색조로 떠오릅니다.
   코어 14개 중 두 개가 75% 이상인 화면에서 그 둘을 찾는 데 값을 하나씩 읽을 필요가 없습니다.

8. 코어 격자에서 색을 지워도 어느 코어가 얼마나 바쁜지 그대로 읽힙니다.
   칸마다 정수 퍼센트가 보이고 막대 채움 높이가 값에 비례하는 것이 유지됩니다.

9. CPU 상세와 Memory 상세가 본체 카드와 같은 시각 언어를 씁니다.
   같은 글자 역할 집합, 같은 여백 단계, 같은 구역 머리글 방식을 쓰며, 상세에만 있는 별도 규칙이 남지 않습니다.

10. Memory 상세의 도넛 범례에서 네 구간의 이름·값·단위가 한 줄에 정렬됩니다.
    도넛을 보지 않고 범례만 읽어도 네 구간의 크기를 비교할 수 있습니다.

11. 이 feature가 더하거나 바꾼 색이 모두 라이트·다크 각각 배경 대비 3:1 이상입니다.
    대비는 근사 배경이 아니라 그 색이 실제로 놓이는 면을 기준으로 재며, 대비가 모자라 다른 조건에 기대는 색이 없습니다.
    바탕과 카드 면 자체도 서로 구분될 만큼 갈립니다.

12. 접근성으로 도달하는 정보가 변경 전과 비교해 하나도 줄지 않습니다.
    카드 접근성 이름의 항목, 코어 칸의 이름·값·식별자, 하위 프로세스 행의 소속 앱과 값이 모두 그대로입니다.

13. 수집 중·정상·실패·중지 사이를 오가도, 상세를 열고 닫아도, 앱 행을 펼치고 접어도
    카드와 팝오버의 크기·위치가 변하지 않습니다.

14. 본체 팝오버와 두 상세의 고정 크기가 새 조립 기준으로 다시 확정됩니다.
    카드 넷을 가정한 세로 합계 계산이 갱신된 카드 높이로 다시 산출되고, 기준 기기에서 성립함이 확인됩니다.
    `ROADMAP.md`와 `docs/design.md`에 적힌 세로 예산 수치가 새 값과 어긋나지 않습니다.

15. 동작 줄이기와 애니메이션 끄기에서 표시가 달라지지 않고,
    팝오버를 열어 둔 채 관찰한 앱 자신의 CPU 사용량이 변경 전과 비교해 지속적으로 상승하지 않습니다.
