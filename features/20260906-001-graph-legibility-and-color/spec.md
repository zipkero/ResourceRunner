# 대시보드 그래프 가독성과 색감 회복 명세

## 1. 범위

이미 동작하는 CPU·Memory 카드와 두 상세 팝업에서 **읽히지 않는 자리와 색이 빠진 자리**를 다룹니다.

표시하는 값·항목·정원·계산·수집은 그대로 두고, CPU 그래프의 크기와 시간 축, 색 집합, 코어 격자의 색,
상세 하위 행의 세로 간격, 카드 순위 안내 문구를 다시 정합니다.

### 관찰된 출발점

사용자가 완성된 화면을 직접 보고 다섯 가지를 지적했습니다(2026-09-06).

- CPU 그래프가 「어디서부터 시작인지도 모르겠고 또 너무 촘촘해서 잘 보이지도 않는다」.
  스크린샷에서 데이터가 오른쪽 끝에만 몰려 있었습니다 —
  가로축 오른쪽 끝이 「그리는 시점」이고 앱을 켠 지 얼마 안 돼 10분 창의 대부분이 비어 있었기 때문이며, 회귀가 아닙니다.
  다만 축 라벨도 시간 눈금도 없어 창의 길이와 데이터의 시작을 알 수 없고, 60pt 높이에 1pt 선이라 값의 오르내림이 뭉갭니다.
- 이어서 두 가지를 덧붙였습니다 — 「가로보다는 세로가 짧다고 느껴진다」와 「그래프가 영역이 잘 느껴지지 않는다」.
  현재 그래프는 카드 콘텐츠 폭 기준 약 232pt × 60pt로 가로세로 비가 약 3.9:1이고,
  기준선이 25·50·75%만 그려져 **0%와 100%에 해당하는 위아래 경계선이 없습니다**.
  직전 feature가 카드의 불투명 채움을 지우면서 그래프 뒤에 남은 면도 없어져,
  그래프가 어디까지인지 화면에 표시하는 요소가 격자 세 줄뿐입니다. 두 지적은 같은 뿌리입니다.
- 「전체적인 앱에 어떤 색감이 없는 거 같다」.
- 「CPU 코어의 색이 없어서 전체적으로 밋밋하다」.
- 상세 팝업에서 「하위 루트의 위 아래가 너무 넓다」.
- 「시스템 프로세스는 TOP 5에 포함되지 않는다는 문구가 굳이 필요한가」.

**앞선 두 지적은 직전 feature가 내린 결정의 결과입니다.**
`20260903-001-dashboard-visual-refinement`의 task-001이 색조를 넷에서 둘로 줄이고 평균 채도를 라이트 64.2 → 43.9,
다크 60.5 → 39.0으로 내렸습니다. 그 방향은 「280pt 폭 안에서 여섯 색이 서로 경쟁한다」는 진단과
iStats Menus 계기판형 선택에서 나왔습니다.
코어 격자가 무채색인 것도 「막대가 나르는 정보는 채움 높이 하나뿐이라 색이 구분에 쓰이는 자리가 없다」는 판단이었습니다.
이 feature는 그 두 판단을 되돌립니다.

세 번째 지적도 마찬가지입니다.
`20260831-001-detail-popover-readability`는 사용자가 「하위 항목들이 너무 붙어 있다」고 해서 세 경계를 벌린 feature였고,
그 결과가 지금의 `2 / 10 / 18 / 26`입니다. 이번에는 반대 방향으로 조입니다.

**2026-09-06 사용자 결정 두 건이 방향을 확정했습니다.**

- 그래프는 카드와 팝오버가 커지더라도 높이를 늘리고 시간 축·눈금을 둡니다.
- 색은 리소스당 고유 색조로 되돌립니다. CPU와 Memory가 서로 다른 색조를 갖고, M3의 Network·Disk도 그렇게 갑니다.
- 색 검증 기준을 줄입니다. **배경 대비 3:1과 「색만으로 구분하지 않는다」 원칙은 유지하고,
  Machado 색맹 시뮬레이션과 인접쌍 ΔE ≥ 8 은 제약에서 뺍니다.**
  앞선 feature들이 그 수치 기준을 쓴 것은 `resource-visualization` 단계에서 design 결정으로 도입해
  이후 spec으로 승격시킨 결과이고, `docs/product.md`·`ROADMAP.md`가 요구하는 것은
  「색상만으로 정상, 경고와 위험을 구분하지 않아야 합니다」라는 원칙과 VoiceOver·동작 줄이기·키보드 탐색뿐입니다.
  대비를 남기는 이유는 색각과 무관하게 밝은 화면·야외에서 읽히지 않는 색을 걸러 내기 때문이고,
  실제로 기존 팔레트는 라이트 모드에서 세 구간이 3:1 미달이었습니다.
  공개 배포를 확정하면 M5 release-readiness 접근성 관문에서 색맹 검증을 한 번 수행합니다.
- 코어 격자 막대는 모든 칸을 같은 색으로 칠하지 않고 **사용률에 따라 단계를 바꿉니다**.
  성능상의 불이익이 없다는 것이 조건이었고, 단계가 유한한 집합이면 칸마다 tick당 드는 일이
  정수 비교와 이미 확정된 색 선택뿐이라 그 조건은 성립합니다.
  연속 그러데이션으로 매 tick 색을 보간하는 방식은 이 판단의 근거가 아닙니다.

검토했으나 접은 방향이 둘입니다.

- 그래프 높이를 그대로 두고 선 두께·불투명도만 올려 가독성을 얻는 방향은 접었습니다.
  60pt 안에서는 10분 창의 오르내림이 여전히 뭉개지고 시간 축을 넣을 자리도 나오지 않습니다.
- 카드에는 작은 스파크라인만 두고 제대로 된 그래프를 상세로 내리는 방향도 접었습니다.
  카드 세로 예산은 아끼지만 「메뉴바에서 최근 흐름을 바로 본다」는 제품 방향이 약해집니다.

**이 feature는 앞선 feature들의 완료 조건을 되엽니다.** 세 자리입니다.

- `20260903-001-dashboard-visual-refinement` `§3`·`§5.10`의 「카드 하나의 높이가 변경 전보다 커지지 않는다」와
  `20260818-001-resource-visualization` `§3`의 같은 제약 — 그래프를 키우려면 성립할 수 없습니다.
- 같은 feature `§3`의 「색조를 셋 이하로 줄인다」와 `§5.6`의 「CPU 한 색조 두 단계, Memory 두 색조 각 두 단계」 —
  리소스당 고유 색조로 가면 성립하지 않습니다.
- `20260831-001-detail-popover-readability`가 픽셀로 확정한 `2 / 10 / 18 / 26` — 값이 줄어듭니다.
  다만 그 feature `§5.1`의 「세 경계가 서로 같은 간격으로 보이지 않는다」는 유지합니다.

되열리는 것은 위 세 자리뿐이며, 그 밖의 완료 조건은 그대로 성립해야 합니다.

## 2. 목표

팝오버를 연 사용자가 **최근 흐름을 눈으로 따라가고, 화면에서 리소스를 색으로 구분**할 수 있게 합니다.

- CPU 그래프에서 값의 오르내림이 뭉개지지 않고, 창이 얼마나 긴지와 데이터가 어디서 시작하는지를 화면에서 알 수 있습니다.
- 그래프가 카드 안에서 차지하는 영역이 눈에 들어오고, 가로에 눌린 띠가 아니라 값을 읽는 면으로 보입니다.
- 앱을 켠 직후처럼 창의 대부분이 비어 있을 때 그 빈 구간이 「값이 0」이 아니라 「아직 수집 전」으로 읽힙니다.
- CPU와 Memory를 색조로 구분해, 어느 카드·어느 상세를 보고 있는지 색만으로도 알 수 있습니다.
- 코어 격자가 화면에서 죽은 영역으로 보이지 않습니다.
- 상세에서 앱을 펼쳤을 때 하위 행 묶음이 필요 이상으로 세로를 먹지 않습니다.
- 카드 순위 자리의 안내가 한 줄을 통째로 차지하지 않습니다.

## 3. 제약

- 표시하는 값·항목·정원·계산·수집 주기를 바꾸지 않습니다. 이 feature는 표시 계층 안에서 끝납니다.
- 그래프의 시간 창은 최근 10분 그대로입니다. 범위 선택 UI는 M4 소관입니다.
- 카드와 본체 팝오버가 커지는 것은 허용하되, **M3에서 카드가 넷이 된 상태의 세로 예산을 함께 계산해
  화면 안에 들어가는 것이 확인되어야 합니다.** 계산 근거를 남기지 않은 확대는 이 제약을 만족하지 않습니다.
- 상세 팝업은 카드 옆에 앵커된 별도 팝오버, 고정 크기, 내부 세로 스크롤 하나라는 구조를 유지합니다.
  고정 크기의 값은 새 표현에 맞춰 다시 확정할 수 있습니다.
- 레이아웃 안정성을 유지합니다.
  수집 중·정상·실패·중지 사이를 오가도, 상세를 열고 닫아도, 앱 행을 펼치고 접어도 크기와 위치가 흔들리지 않습니다.
  아직 값이 없는 그래프·순위 자리는 비워 두지 않고 같은 높이의 자리표시로 채웁니다.
- 값을 지어내지 않습니다. 수집되지 않은 구간을 0으로 그리거나 선으로 이어 붙이지 않습니다.
- 색만으로 정보를 전달하지 않습니다.
  계열·구간·코어는 색 외의 수단(라벨·기호·수치·채움 밀도·경계선 모양·채움 높이)으로도 구분됩니다.
- 새 색 집합은 배경 대비 3:1 이상을 통과해야 합니다.
  라이트와 다크는 각각 따로 확정하고 한쪽 값에서 반전으로 유도하지 않습니다.
  3:1을 만족하지 못하는 구간이 남으면 그 구간에 한해 스와치 옆 이름이 항상 보이는 relief 조건을 유지합니다.
  색맹 시뮬레이션과 인접쌍 ΔE 기준은 이 feature의 제약이 아닙니다(2026-09-06 결정).
  대신 아래 「색만으로 정보를 전달하지 않습니다」가 색 구분 실패의 안전망을 맡습니다.
- 리소스마다 고유 색조를 갖되, M3에서 Network·Disk가 더해져도 같은 규칙으로 확장될 수 있어야 합니다.
- 코어 격자의 색이 채움 높이·수치가 이미 나르는 정보를 대체하지 않습니다.
  색을 지운 화면에서 코어 사이 높낮이 비교가 지금과 같은 정도로 성립해야 합니다.
- 코어 막대의 사용률 단계는 **유한한 집합**이며 갱신 주기마다 색을 보간하지 않습니다.
  각 단계 색은 미리 확정된 상수여야 하고, tick마다 하는 일은 값이 어느 단계에 드는지 고르는 것까지입니다.
- 코어 막대의 단계 색이 「정상·경고·위험」 같은 상태 신호로 읽히지 않아야 합니다.
  Memory Pressure는 색을 쓰지 않고 기호와 라벨로만 세 단계를 나타내며(`docs/product.md` 「색상만으로 정상,
  경고와 위험을 구분하지 않아야 합니다」), 코어 사용률은 그와 다른 종류의 값입니다.
- 코어 막대의 각 단계 색은 배경 대비 3:1 이상을 통과해야 하며, 단계 수를 늘리는 만큼
  라이트·다크 양쪽에서 통과 가능한 명도 구간이 좁아진다는 점을 함께 고려해 단계 수를 정합니다.
- 하위 프로세스 행의 세 경계가 서로 같은 간격으로 보이지 않아야 합니다.
  구분 수단은 들여쓰기와 간격뿐이며 구분선·배경·테두리를 쓰지 않습니다.
- 카드에서 시스템 프로세스가 순위에 포함되지 않는다는 사실을 확인할 수 있어야 합니다.
- 변경 전에 접근성 계층에서 이름·값으로 도달했던 요소는 변경 후에도 같은 범위로 도달합니다.
- 동작 줄이기와 애니메이션 끄기에서도 같은 정보를 확인할 수 있어야 하며, 새 표현이 애니메이션을 전제하지 않습니다.
- 이 앱 자체가 리소스 모니터이므로, 새 표현이 갱신 주기마다 지속적인 CPU 부하를 더하지 않습니다.
- App Sandbox를 유지하고 새 entitlement를 추가하지 않습니다.

## 4. 제외 범위

- 그래프 시간 범위 선택(1분·5분·10분)과 그 설정 저장. M4 앱 설정 소관입니다.
- Memory 카드에 시계열 그래프를 더하는 것. Memory는 구성 누적 바와 도넛을 그대로 씁니다.
- 값의 정의·계산·수집 주기·이력 링 용량·평활화 창 변경.
- Network·Disk 카드의 표현. M3 소관이며 이 feature는 색조 규칙이 확장 가능하다는 것만 요구합니다.
- 표시 항목의 추가·삭제. 순위 정원 변경.
- 상세 팝업을 별도 창으로 승격하거나 본체 안 인라인 확장으로 바꾸는 구조 변경.
- 하위 프로세스 행의 구분 수단을 들여쓰기·간격 외의 것으로 바꾸는 것.
- 카드 표면·타이포 계층·값 정렬 규칙 변경. 직전 feature가 확정했고 이번 지적 대상이 아닙니다.
- 메뉴바 캐릭터 자산·아이콘·애니메이션.
- 라이트·다크 외의 테마와 사용자 색 선택.

## 5. 완료 조건

1. CPU 카드 그래프의 높이가 변경 전보다 커지고, 최근 10분 창에서 값의 오르내림이 선으로 구분되어 읽힙니다.
   그래프의 가로세로 비가 변경 전(약 3.9:1)보다 낮아져 가로에 눌린 띠로 보이지 않습니다.
   User와 System 두 계열 구분과 기준선은 그대로 유지됩니다.
2. 그래프에서 시간 창의 길이와 데이터가 시작하는 자리를 화면에서 알 수 있습니다.
   앱을 켠 직후처럼 창의 대부분이 비어 있어도 그 빈 구간이 값 0이 아니라 아직 수집되지 않은 구간으로 구분됩니다.
3. 카드와 본체 팝오버가 커진 상태에서, M3의 카드 넷을 가정한 세로 합계가 화면 안에 들어간다는 계산 근거가 확인됩니다.
4. CPU와 Memory가 서로 다른 색조로 표시되어 화면에서 두 리소스를 색으로 구분할 수 있고,
   CPU 상세의 코어 격자 막대가 사용률에 따라 유한한 단계의 색으로 표시됩니다.
   색을 지운 화면에서 계열·구간 구분과 코어 사이 높낮이 비교가 변경 전과 같은 정도로 성립하고,
   단계 색이 상태 경고로 읽히지 않습니다.
5. 새 색 집합이 §3의 색 기준(배경 대비 3:1 또는 relief 조건)을 통과한 결과가 확인됩니다.
6. 상세 팝업에서 앱 행을 펼쳤을 때 하위 행 묶음이 차지하는 세로가 변경 전보다 줄고,
   부모–첫 하위·하위끼리·마지막 하위–다음 앱 세 경계가 여전히 서로 같은 간격으로 보이지 않습니다.
7. 카드 순위 자리의 시스템 프로세스 안내가 한 줄을 통째로 차지하지 않으면서,
   시스템 프로세스가 순위에 포함되지 않는다는 사실을 카드에서 확인할 수 있습니다.
8. 위 변경이 모두 있는 상태에서 수집 중·정상·실패·중지 사이를 오가도, 상세를 열고 닫아도,
   앱 행을 펼치고 접어도 카드와 팝오버의 크기·위치가 변하지 않습니다.
9. 변경 전에 접근성 계층에서 이름 또는 값으로 도달했던 요소가 변경 후에도 같은 범위로 도달합니다 —
   카드의 상태와 주요 수치, 그래프의 계열과 기준선, 코어 칸의 번호와 사용률, 하위 프로세스 행의 소속 앱과 값입니다.
10. 동작 줄이기와 애니메이션 끄기 설정에서 위 표시가 모두 같은 정보를 전달합니다.
11. 팝오버를 열어 둔 채 관찰한 앱 자신의 CPU 사용량이 변경 전과 비교해 지속적으로 상승하지 않습니다.
12. 논리 코어 14개인 기기에서 코어 격자 전체가 CPU 상세의 첫 화면에 스크롤 없이 들어오는 상태가 유지되고,
    코어 수가 그보다 적거나 많아도 배치가 코어 수를 따라갑니다.
13. 그래프가 차지하는 영역의 경계가 화면에서 구분되어, 값이 0에 가까울 때와 100%에 가까울 때가
    같은 면 안의 아래쪽·위쪽으로 읽힙니다.
    이 경계는 값이 없는 자리표시 상태에서도 같은 자리에 같은 크기로 나타납니다.
