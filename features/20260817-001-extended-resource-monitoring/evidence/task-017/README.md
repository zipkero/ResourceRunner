- 범위: `/tmp`는 `/dev/disk3s5`의 APFS Data 볼륨이고, 그 container의 physical store가 `disk0s2`다(`storage-path.txt`). 앱의 물리 통계 owner는 `IOBlockStorageDriver` registryID **4294969732**, BSD **disk0** 한 개였으며 유효 표본 내내 identity와 topology revision 1, epoch 0, rate segment 1이 유지됐다. `iostat -d -w 1 disk0`도 같은 물리 BSD 범위다. 앱의 `physicalTotalsComplete=true`와 카드 `partial=false`를 이 세션에서 확인했다. APFS 볼륨별 사용량을 물리 속도에 중복 합산하지 않는다.
- 부하: 앱 밖 `observe.py`가 `/tmp/rr-task017-synthetic-*` 안에 256MiB 합성 파일을 만들고 `F_NOCACHE`를 켠 파일 디스크립터에 1MiB `pread`/`pwrite`를 약 32회/초 실행했다. Read·Write 각각 유휴 **15초 → 부하 30초 → 회복 15초**이며 두 부하 모두 정확히 960MiB(1,006,632,960B)를 처리했다(`events.jsonl`). 쓰기는 8회마다, 끝에서 `fsync`했다. 준비 쓰기 뒤 5초 안정을 두고 실제 측정을 시작했다. 이 파일은 종료 시 삭제됐다. 부하·`iostat`·TSV/PNG 기록 I/O는 외부 관찰/DEBUG probe 작업이다. 제품 Collector는 native `IOBlockStorageDriver` 통계를 읽으며, `ResourceRunner/` 소스에서 `Process(`, `iostat`, `pread`, `pwrite`, `F_NOCACHE` 호출은 검색되지 않았다.
- 비교: [Apple 공개 `iostat.c`의 `devstats`](https://github.com/apple-oss-distributions/system_cmds/blob/main/iostat/iostat.c)는 드라이버 BytesRead+BytesWritten의 차분을 합하고 `MB/s`를 **1,048,576B**로 나눠 계산한다. 따라서 도구의 MB/s는 Read+Write 합산이고, 앱의 방향별 B/s 또는 UI의 decimal MB/s와 단위를 구분한다. `iostat` 첫 수치 행은 부팅 이후 평균이어서 제외하고 후속 1초 구간만 썼다. `analyze.py`는 각 phase 시작·끝 3초 전환 구간과 baseline/failure를 판정에서 빼되 원문 `app-samples.tsv`, `iostat.raw.txt`, `events.jsonl`은 보존한다. 구간별 유효 표본 수, 최소/최대, 원시 드라이버 첫·끝 바이트와 시각은 `comparison.json`에 있다. 원시 **절대 누적값의 앱/도구 일치나 개별 표본의 수치 일치율을 주장하지 않고**, 동일 물리 범위의 차분 및 변화 방향만 판단한다. 별도 허용 오차·성능 기준은 추가하지 않았다.
