# 사용자 설정과 로그인 시 실행 명세

## 1. 범위

M4의 첫 범위는 메뉴바에서 접근하는 설정 화면, 카드·TOP 5 표시,
그래프 시간 범위, 갱신 4단계, 로그인 시 자동 실행과 기본값 복원입니다.
설정은 앱 재시작 없이 반영되고 재시작 후에도 유지됩니다.
캐릭터·애니메이션 제작과 관련 설정은 기존 결정대로 후속 작업에 둡니다.

### 1.1 입력 맥락

- 사용자 요청: `$spec-init m4`, 이후 범위 선택에서 “권장” 승인(2026-10-03).
  카드·TOP 5 표시, 그래프 1/5/10분, 갱신 4단계, 로그인 자동 실행, 기본값 복원만 이번에 포함합니다.
- [프로젝트 README](../../README.md)의 주요 기능·개인정보 원칙,
  [ROADMAP](../../ROADMAP.md)의 「M4. 사용자 설정과 로그인 시 실행」을 기준으로 합니다.
- [제품 정의](../../docs/product.md)의 「설정」·「최근 그래프와 데이터 보관」·
  「로그인 시 자동 실행」·「데이터와 개인정보」에서 해당 범위의 요구사항을 사용합니다.
- [기술 설계](../../docs/design.md)의 「현재 확인된 구현」·「사용자 갱신 프로필」·
  「생명주기 반영」·「데이터 저장」을 다음 단계의 조사 출발점으로 사용합니다.
- 구현 조사 기준은 `main`, HEAD `0b01a9b`입니다.
  `ResourceRunner/ResourceRunnerApp.swift`의 Settings는 EmptyView이며 설정 저장·로그인 항목 관리가 없습니다.
  `MonitoringLifecycle.swift`는 여섯 축의 주기와 화면을 볼 수 없는 상태의 중지를 소유합니다.
  `MonitoringSampleStore.swift`·`ResourceRateGraph.swift`의 현재 시간 창은 10분이며,
  `ApplicationRanking.swift`의 현재 카드 정원은5, 상세 정원은20입니다.
  이 사실은 구현 완료 주장이 아니라 DESIGN의 조사 입력입니다.
- 선행 M3는 [extended-resource-monitoring](../20260817-001-extended-resource-monitoring/README.md)의
  task001~008/010~013/016~018을 승인했습니다. task014의 실제 연결 전환과 task015의 잠금·절전 복귀는 미완료입니다.
  사용자 지시에 따라 이 보류 관문은 M4 착수를 막지 않는 예외로 두며, M3 전체 완료로 전환하지 않습니다.
  M4 작성으로 기존 SPEC·DESIGN·Task 승인을 취소하지 않습니다.
- 본체 스크롤 없이 읽을 수 있는 한 열 요약, Memory 자연 높이, Network 그래프 없음,
  Disk 수치 옆 미니 그래프와 상세·접근성 정보 보존은
  [M3 DESIGN](../20260817-001-extended-resource-monitoring/design.md)의 최신 계약을 따릅니다.

### 1.2 표시·그래프 설정

| 설정 | 선택 | 기본값 |
| --- | --- | --- |
| CPU·Memory·Network·Disk 카드 표시 | 카드별 켜기/끄기 | 네 카드 모두 켜기 |
| CPU·Memory TOP 5 표시 | 카드별 켜기/끄기 | 둘 다 켜기 |
| 그래프 시간 범위 | 최근1분·5분·10분 | 최근10분 |

카드 표시와 TOP 5 표시는 화면 구성 설정입니다. 메뉴바의 실제 상태 판정과 현재 수치의 의미를 바꾸지 않습니다.
TOP 5를 숨겨도 해당 카드의 대표 수치·기존 그래프/구성 표시와 상세 정보는 유지됩니다.
숨긴 카드·순위의 자리를 빈 공간으로 예약하지 않습니다.
모든 카드를 숨겨도 설정에 접근하고 카드를 다시 켤 수 있으며, 본체는 카드가 숨겨진 상태임을 설명합니다.
숨긴 카드의 상세가 열려 있었다면 상세를 닫고 사용 가능한 화면으로 복귀합니다.

시간 범위는 이미 존재하는 CPU·Disk의 시간축 그래프에 공통 적용합니다.
축·범위 안내·데이터 수집 중 표시와 실제로 표시한 구간이 일치해야 합니다.
Network 그래프나 Memory 시간축 그래프를 새로 만들지 않으며, Memory 구성 도넛/막대는 현재 구성 표시로 유지합니다.
범위를 늘리거나 주기를 바꿔도 존재하지 않는 과거 샘플을 만들지 않습니다.

### 1.3 갱신 설정

사용자는 내부 타이머를 축별로 직접 조절하지 않고 빠름·기본·절전·매우 절전 중 하나를 선택합니다.
기본값은 기본이며, 기존 기술 설계의 아래 값을 이번 명세의 기준으로 사용합니다.

| 프로필 | 열림 전체 지표 | 열림 TOP 5 | 닫힘 전체 지표 |
| --- | ---: | ---: | ---: |
| 빠름 | 0.5초 | 1초 | 1초 |
| 기본 | 1초 | 2초 | 2초 |
| 절전 | 2초 | 4초 | 5초 |
| 매우 절전 | 5초 | 5초 | 10초 |

전체 지표는 CPU·Memory와 Network·Disk의 빠른 활동을 뜻합니다.
닫힌 상태의 순위 감속과 저전력 모드 정책은 기존 생명주기 제어와 함께 적용하며,
선택한 절전 프로필이 저전력 전환 때문에 더 빠른 프로필로 바뀌지 않아야 합니다.
저장 공간·인터페이스 보조 정보는 빠른 지표와 별도 느린 주기를 유지합니다.
자동 감속을 해제하거나 잠금 중 수집을 강제로 계속하는 설정은 이번 범위에 없습니다.
프로필별 닫힘 순위·보조 일정과 저전력 병합의 구체적인 계산은 이 제약을 충족하도록 DESIGN에서 확정합니다.

### 1.4 저장·기본값 복원·로그인 항목

사용자 설정값만 macOS 기본 설정 저장소에 보관합니다.
설정 화면과 실제 표시·수집이 같은 유효 설정을 사용하며, 재시작 시 첫 화면과 최초 일정부터 저장값을 적용합니다.
저장값이 없거나 지원하지 않는 값이면 해당 설정의 기본값을 사용합니다.

기본값 복원은 네 카드와 두 TOP 5 표시 켜기, 최근10분, 기본 갱신 프로필로 되돌리고 저장·즉시 반영합니다.
로그인 자동 실행의 기본은 자동 등록하지 않는 상태입니다.
최초 설정 로드만으로 기존 macOS 로그인 항목을 등록·해제하지 않습니다.
로그인 설정의 표시 상태는 별도 저장한 켜기/끄기 값 대신 macOS의 실제 등록·허용 상태를 기준으로 합니다.
사용자가 로그인 설정을 변경하거나 기본값 복원을 실행하면 그 의도에 맞는 등록·해제를 요청합니다.
실패 또는 macOS 승인이 필요한 상태에서는 원하는 값으로 성공 표시하지 않고 실제 상태와 필요한 사용자 동작을 설명합니다.
다른 설정의 복원 결과와 로그인 항목 처리 결과를 구분해 표시합니다.

## 2. 목표

- 메뉴바 앱 안에서 표시와 갱신 방식을 간단히 조절하고 다음 실행에서도 같은 설정을 사용합니다.
- 설정 변경이 현재 수집과 표시를 끊거나 잘못된 속도·이력을 만들지 않습니다.
- 사용자가 앱과 macOS 시스템 설정에서 로그인 시 실행의 실제 상태를 일관되게 확인합니다.
- 기본값으로 복귀할 수 있고, 카드 숨김이나 잘못된 저장값 때문에 설정에 접근하지 못하는 상태를 만들지 않습니다.

## 3. 제약

- macOS26.5 이상·Apple silicon·arm64·App Sandbox와 기존 배포 구성을 유지합니다.
  별도 Helper·관리자 권한·시스템 확장·외부 package를 추가하지 않습니다.
  로그인 항목은 공개 native 기능으로 메인 ResourceRunner 앱만 등록하며 LaunchDaemon·LaunchAgent 파일을 직접 설치하지 않습니다.
- 앱은 설정 변경에 재시작을 요구하지 않습니다. 수집 관련 변경은 다음 일정부터 반영하며 타이머·수집 작업을 중복 생성하지 않습니다.
  변경 전에 시작한 요청이 새 설정·실행권의 값을 덮어쓰지 않아야 합니다.
- 속도는 실제 샘플 시각의 차분으로 계산합니다. 화면을 볼 수 없는 상태의 수집 중지·재개 기준점,
  중지 구간의 그래프 공백, 실패 격리, 물리/부분 합계·보조 정보의 의미를 유지합니다.
- 빠름 프로필에서도 선택 가능한10분 창과 실제 경과 시간에 맞는 제한된 메모리 이력을 사용합니다.
  그래프 범위 선택을 Memory 증가 순위 등 별도 계산 정의를 바꾸는 설정으로 사용하지 않습니다.
- 기본 표시에서는 M3의 읽을 수 있는 스크롤 없는 네 카드와 Memory 하단 여백 수정 결과를 보존합니다.
  표시 항목을 줄인 경우에도 본체에 스크롤이나 불필요한 예약 공백을 추가하지 않습니다.
  작은 화면의 미확정 정책을 M4에서 임의로 바꾸지 않습니다.
- 설정은 키보드와 접근성으로 조작할 수 있고, 숨긴 카드의 기존 단축키는 다른 카드에 재배정하지 않습니다.
  현재 리소스의 색상 외 상태 설명과 상세 정보 접근성을 유지합니다.
- 수집값·프로세스 목록·TOP 5·인터페이스/장치 정보·최근 그래프는 메모리에만 보관합니다.
  설정 저장을 이유로 이를 파일이나 기본 설정 저장소에 기록하거나 외부로 전송하지 않습니다.
  로그인 상태는 macOS를 기준으로 하고 일반 설정 저장과 혼동하지 않습니다.
- 이번 단계의 산출물은 spec.md·상태 README.md 및 관련 진행 문서입니다.
  API 선택·설정 화면 배치·저장 키·일정 계산의 설계와 제품 구현은 다음 단계에서 수행합니다.

## 4. 제외 범위

- 시스템 프로세스 필터, 상세 목록 정원 변경, 팝오버 자동 닫기 옵션.
  현재 상세 정원·프로세스 집계와 transient 팝오버 동작을 유지합니다.
- 애니메이션 활성화·캐릭터 선택·최대 FPS·Memory Pressure/Disk/Network 효과 설정과 자산 제작.
  기존 결정대로 캐릭터·애니메이션 작업 때 함께 다룹니다.
- 앱 업데이트 확인·자동 업데이트·서명/공증된 배포물 제작과 M5의 성능·장기 안정성 관문.
- 축별 사용자 정의 주기, 자동 감속 해제, 잠금 중 수집 계속 옵션.
- 장기 통계,1/5/10분 외 시간 범위, 재시작 후 그래프 복원, 설정 내보내기·동기화·원격 서비스.
- M3 task014/015의 실제 연결 전환·잠금·절전 복귀 검증 재개 또는 완료 처리.
  로그인 구현 때문에 잠금·로그아웃·재부팅 검증을 이번 SPEC 작성 중 실행하지 않습니다.

## 5. 완료 조건

1. 메뉴바에서 설정 화면에 접근할 수 있고 카드 표시 조합과 무관하게 다시 설정할 수 있습니다.
   모든 카드를 숨긴 상태도 설명과 복구 경로가 있으며 설정 접근 경로가 사라지지 않습니다.
2. 네 카드 표시를 각각 켜고 끌 수 있고 즉시 본체에 반영됩니다.
   숨긴 카드의 상세는 닫히며 숨긴 자리의 예약 공백이 없습니다.
   네 카드가 기본으로 켜진 상태에서는 기존 스크롤 없는 배치가 유지됩니다.
3. CPU·Memory의 TOP 5를 각각 켜고 끌 수 있고 기본값은 둘 다 켜기입니다.
   순위를 숨겨도 대표 수치·기존 그래프/구성과 상세 정보는 유지되고 순위 자리의 예약 공백은 없습니다.
4. 최근1/5/10분을 선택하면 기존 CPU·Disk 시간축 그래프의 범위·축 안내·수집 중 표시가 즉시 같은 구간으로 바뀝니다.
   기본값은10분이며 Network 그래프나 Memory 시간축 그래프가 추가되지 않습니다.
   범위 확대·재시작 때 존재하지 않는 과거 샘플을 생성하지 않습니다.
5. 빠름·기본·절전·매우 절전이 §1.3의 열림 지표/TOP 5·닫힘 지표 주기로 반영됩니다.
   기존 닫힘 감속·저전력·화면을 볼 수 없는 상태의 중지와 느린 보조 수집이 함께 유지되고,
   저전력 전환이 사용자 절전 선택을 더 빠르게 만들지 않습니다.
6. 갱신 설정 변경은 재시작 없이 다음 일정부터 적용되며 중복 타이머·동시 실행·오래된 요청의 새 상태 덮어쓰기가 없습니다.
   실제 경과 시간 속도·새 기준점·중지 구간 공백과 Collector별 실패 격리가 유지됩니다.
7. 사용자 설정값은 저장되고 재실행 첫 화면·최초 일정부터 복원됩니다.
   빠름에서도 선택한10분의 실제 시간 창을 지원하는 제한된 이력을 사용하며, 설정 외 수집 데이터는 재시작 복원되지 않습니다.
8. 설정 저장값이 없거나 손상·미지원 값이면 지원되는 기본값으로 복구됩니다.
   사용자가 선택할 수 없는 주기·범위·표시 상태가 저장값 복원으로 활성화되지 않으며 설정 화면과 실제 적용값이 일치합니다.
9. 기본값 복원이 표시·TOP 5·시간 범위·갱신 설정을 §1의 기본값으로 저장하고 즉시 반영합니다.
   로그인 자동 실행은 기본인 해제 의도를 적용하되 실패/승인 상태를 실제 결과대로 설명합니다.
10. 로그인 자동 실행은 메인 ResourceRunner 앱만 공개 native 기능으로 등록·해제하고,
    별도 Helper·관리자 권한·LaunchDaemon·LaunchAgent 직접 설치를 사용하지 않습니다.
