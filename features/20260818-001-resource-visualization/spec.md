# CPU·Memory 대시보드 시각화와 순위 표시 명세

## 1. 범위

이 feature는 이미 동작하는 CPU·Memory 카드와 상세 팝업이 **값을 어떻게 보여주는지**를 다룹니다.
수집 계층과 순위 계산 규칙은 그대로 두고, 표시 계층에서 읽히는 정도를 바꿉니다.

네 가지를 포함합니다 — 상세 팝업의 순위 정원 확장과 CPU 상세 앱 순위 섹션 신설,
Memory의 구성 항목 시각화, CPU 그래프의 격자와 User·System 2계열 표현, 목록의 앱 아이콘.

### 입력 맥락

- [ROADMAP.md](../../ROADMAP.md)의 `M2. 핵심 리소스 모니터링`: CPU·Memory 카드가 담당하는 결과와 범위 경계.
- [docs/product.md](../../docs/product.md)의 `CPU`, `Memory`: 기본 카드와 상세에 담을 항목, TOP 5 정책.
- [docs/product.md](../../docs/product.md)의 `대시보드 > 공통 정보 구조`: 선택 시 카드 옆 팝업, 레이아웃 안정성.
- [docs/product.md](../../docs/product.md)의 `미확정 제품 결정`과 `표시` 설정 후보:
  「CPU·Memory TOP 5 표시 여부」와 「그래프 시간 범위」가 설정 후보로 올라 있습니다.
- [features/20260812-001-core-resource-monitoring/spec.md](../20260812-001-core-resource-monitoring/spec.md):
  이 feature가 얹히는 기반. 특히 `§5.1`(카드 표시 항목), `§5.2`(상세 항목), `§5.6`(앱 단위 묶음과 순위 안정성),
  `§5.11`(값을 지어내지 않음), `§5.15`(레이아웃 안정성).

**이 feature는 `docs/product.md`의 요구사항을 바꿉니다.** 두 자리입니다 —
`§TOP 5 정책`이 상한을 5로 못박고 있어 상세 20을 담지 못하고,
`§Memory > 기본 카드`에 그래프 항목이 없어 시각화를 담지 못합니다.
spec 승인 뒤 `docs/product.md`를 함께 갱신해야 하며, 그 갱신 없이는 이 spec이 루트 문서와 어긋난 상태로 남습니다.

### 관찰된 출발점

사용자가 실행 중인 앱에서 세 가지를 보고했습니다.

- CPU 그래프가 너무 조밀해 읽히지 않음 — core-resource-monitoring에서 다운샘플링으로 해소했습니다.
- CPU 상세 목록이 "그냥 나열해두고 목록 열어서 보든가 하는 느낌" —
  같은 feature에서 정렬 비결정성·값 미표시·펼침 조작을 해소했고, **개수 상한만 남았습니다.**
- Memory에도 그래프가 필요하며 CPU 같은 선 그래프가 아니라 원형이나 바 형태.

참고 앱 스크린샷(CleanMyMac Memory·CPU 패널, iStat Menus 드롭다운)에서 읽어낸 것 중
이 feature가 받아들이는 것은 넷입니다 — 구성 항목을 색 구간으로 나눈 링·바,
대표 수치를 가운데 두고 옆에 색점 범례를 쌓는 배치,
User·System을 겹쳐 그리고 뒤에 격자를 깐 CPU 시계열, 목록 행의 앱 아이콘.

검토했으나 접은 것 — 프로세스 종료(Quit) 버튼은 참고 앱 셋 모두 갖고 있으나 §4로 뺐습니다.
그래프 시간 범위 선택(1분·5분·10분)은 `docs/product.md` 1.0 범위에 있으나 설정 UI가 필요해 §4로 뺐습니다.
Memory 카드 높이를 늘리는 방향도 접었습니다 — 대신 지금 텍스트로 있는 줄을 그래프가 흡수합니다.

구성 항목 시각화의 기준은 확정했습니다.
참고 앱은 구간 합이 「전체 − 여유」와 정확히 맞아떨어지지만 이 앱에서는 그 관계가 성립하지 않습니다 —
「사용 중」이 Activity Monitor 공식(`total − (free − speculative) − external`)을 따르도록
core-resource-monitoring task-001에서 확정됐고, 이 값은 `App + Wired + Compressed`와 다릅니다.
그래서 구간 합을 「사용 중」에 맞추는 두 방식을 접었습니다 —
「사용 중」 정의를 되돌리면 Activity Monitor와의 편차 0 일치가 깨지고,
「사용 중」을 바의 채운 길이로 삼아 안쪽을 비율로 나누면 구간 길이가 실제 바이트에 비례하지 않아 값이 왜곡됩니다.
채택한 방향은 둘을 별개 지표로 분리하는 것입니다.

상세 팝업의 순위 표시 방식도 확정했습니다.
core-resource-monitoring이 전체 프로세스 목록을 사용량순으로 정렬하고 앱 행에 합계값을 표시하도록 고친 결과,
그 목록 자체가 이미 순위입니다. 여기에 순위 섹션을 따로 두면 상위 항목이 한 화면에 두 번 나타납니다.
그래서 목록 하나에 정원을 걸어 순위와 하위 프로세스 확인을 같은 자리에서 하도록 통합합니다.
Memory 상세에 이미 있던 「현재 사용량 순위」와 전체 목록의 중복도 이 통합으로 함께 해소됩니다.
증가량 순위는 현재 사용량과 다른 지표라 별도로 남습니다.

## 2. 목표

카드와 상세를 열었을 때 **무엇이 리소스를 쓰고 있고 그 규모가 어느 정도인지**를
숫자를 하나씩 읽지 않고 판단할 수 있게 합니다.

- CPU 상세에서 상위 소비 앱을 5개 너머까지 보고, 그 앱이 어떤 하위 프로세스로 구성되는지 같은 화면에서 확인합니다.
- Memory의 구성이 한눈에 보입니다 — 지금은 App·Wired·Compressed·Cached가 상세의 텍스트 한 줄에만 있습니다.
- CPU 그래프에서 부하가 User인지 System인지 구분되고, 값의 높이를 격자로 어림할 수 있습니다.
- 목록에서 앱을 이름 대신 아이콘으로 먼저 알아봅니다.

## 3. 제약

- 카드 크기와 위치는 이 feature 때문에 커지지 않습니다.
  본체 팝오버 높이는 두 카드에 맞춰 실측한 값이고 M3에서 카드가 넷으로 늘어납니다.
  Memory 시각화는 새 공간을 요구하지 않고 지금 텍스트로 있는 줄을 대체해야 합니다.
- 순위 계산 규칙과 평활화 창을 바꾸지 않습니다.
  카드 TOP 5와 상세 목록이 같은 값·같은 순서를 쓰는 관계가 유지되어야 합니다.
- 값을 지어내거나 왜곡하지 않습니다.
  기준점이 없어 만들 수 없는 값은 0이나 추정값으로 채우지 않고,
  그래프의 구간·계열 길이는 실제 값에 비례해야 합니다.
- 「사용 중」과 구성 항목 합계는 정의가 다른 별개 지표이며, 화면에서 같은 값처럼 보이게 두지 않습니다.
- 색만으로 정보를 전달하지 않습니다. 구간·계열은 색 외의 수단(라벨·기호·수치)으로도 구분됩니다.
- 상세 팝업의 고정 크기와 내부 스크롤 구조를 유지합니다.
- 아이콘 로드와 순위 정원 확대가 갱신 주기마다 지속적인 CPU 부하를 만들지 않습니다.
  이 앱 자체가 리소스 모니터이므로 자기 사용량이 제품 제약입니다.
- App Sandbox를 유지하고 새 entitlement를 추가하지 않습니다.
- 프로세스 조사 실패·중지 상태에서도 새 표시 요소가 레이아웃을 흔들지 않습니다.

## 4. 제외 범위

- 프로세스 종료(Quit)와 그 밖에 프로세스 상태를 바꾸는 모든 조작.
  읽기 전용 모니터링 범위를 넘고 `docs/product.md` 1.0 범위에 없으며, Sandbox 권한과 오조작 복구 설계가 따라옵니다.
- 그래프 시간 범위 선택(1분·5분·10분)과 그 설정 저장. M4 앱 설정 소관입니다.
- 표시 항목·순위 정원·시스템 프로세스 포함 여부를 사용자가 고르는 설정.
- Network·Disk 카드의 시각화. M3 extended-resource-monitoring 소관입니다.
- 수집 주기·이력 링 용량·평활화 창 변경.
- 「사용 중」 메모리의 정의 변경.
- 프로세스 검색·즐겨찾기, 30분 이상 그래프, 데이터 내보내기.
- 메뉴바 캐릭터 자산과 애니메이션.

## 5. 완료 조건

1. CPU 상세를 열면 앱 단위 CPU 사용량 순위가 카드의 5개보다 큰 정원으로 표시되고,
   같은 목록에서 각 앱의 하위 프로세스를 펼쳐 확인할 수 있습니다.
   같은 순위가 한 화면에 두 번 나타나지 않습니다.
   Memory 상세는 현재 사용량과 최근 증가량을 서로 다른 지표로 구분해 제공하며 같은 정원을 씁니다.
   카드의 순위 자리는 5개를 유지합니다.
2. 상세 순위의 상위 5개 항목과 순서가 같은 시점 카드 순위와 일치합니다.
3. Memory 카드에 App·Wired·Compressed·Cached 구성이 하나의 그래프로 표시되고,
   각 구간이 색 외의 수단으로도 구분되며 수치를 확인할 수 있습니다.
   각 구간의 길이는 전체 물리 메모리를 기준으로 실제 바이트에 비례하고,
   구성 합계와 「사용 중」 수치는 서로 다른 지표로 구분되어 읽힙니다.
   카드의 크기와 위치는 이 그래프가 없던 상태와 같습니다.
4. Memory 상세를 열면 같은 구성이 카드보다 큰 형태로 표시되고 각 항목의 수치가 범례로 함께 보입니다.
5. CPU 카드 그래프에 User와 System이 구분되어 표시되고, 두 계열의 합이 같은 시점 전체 CPU 사용률과 일치합니다.
6. CPU 카드 그래프에 값의 높이를 어림할 수 있는 기준선이 표시됩니다.
7. 앱 단위 순위와 상세 목록의 각 행에 그 앱의 아이콘이 표시되고,
   아이콘을 얻을 수 없는 항목도 행 높이와 정렬이 흔들리지 않습니다.
8. 위 표시 요소가 모두 있는 상태에서 수집 중·정상·실패·중지 사이를 오가도
   카드와 상세 팝업의 크기·위치가 변하지 않습니다.
9. 새 표시 요소가 더해진 뒤에도 팝오버를 열어 둔 채 관찰한 앱 자신의 CPU 사용량이
   변경 전과 비교해 지속적으로 상승하지 않습니다.
10. 카드와 상세의 새 표시 요소가 접근성 계층에서 이름과 수치로 도달됩니다.
