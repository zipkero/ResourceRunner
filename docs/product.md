# 제품 정의

## 문서 목적

이 문서는 ResourceRunner가 사용자에게 제공해야 하는 제품 동작과 1.0 범위를 정의합니다.

- [README.md](../README.md)는 제품 소개, 주요 기능과 프로젝트 문서 진입점을 제공합니다.
- [ROADMAP.md](../ROADMAP.md)는 최종 결과물, 마일스톤과 출시 관문을 정의합니다.
- [design.md](./design.md)는 이 제품 동작을 구현하기 위한 기술 설계와 검증 전략을 정의합니다.
- 각 feature의 상세 완료 조건은 해당 작업을 시작할 때 feature spec에서 확정합니다.

이 문서의 내용은 목표 제품 요구사항입니다. 현재 구현 상태는 ROADMAP.md의 현재 상태와
design.md의 현재 구현을 기준으로 판단합니다.

## 대상 사용자와 문제

ResourceRunner는 다음 사용자를 대상으로 합니다.

- 시스템 상태를 항상 확인하고 싶지만 별도 분석 창을 계속 열어 두고 싶지 않은 macOS 사용자
- 빌드, 가상화, 브라우저와 개발 도구의 부하 원인을 빠르게 확인하려는 개발자
- CPU, 메모리, 네트워크와 디스크 흐름을 한 화면에서 파악하려는 전력 사용자

ResourceRunner는 다음 두 도구 사이의 간극을 채우는 것을 목표로 합니다.

- 가볍지만 현재 수치만 보여주는 메뉴바 모니터
- 상세하지만 필요할 때마다 별도 창을 열어야 하는 시스템 분석 도구

핵심 목표는 다음과 같습니다.

1. 메뉴바만 보고도 현재 시스템 부하를 대략 파악할 수 있어야 합니다.
2. CPU나 메모리 사용량이 높을 때 원인 프로세스를 즉시 확인할 수 있어야 합니다.
3. 현재값뿐 아니라 최근 몇 분간의 흐름을 그래프로 확인할 수 있어야 합니다.
4. 모니터링 앱 자체가 시스템 부하의 원인이 되지 않아야 합니다.
5. 별도 Helper, 관리자 권한과 시스템 확장을 요구하지 않아야 합니다.
6. 수집한 데이터는 기본적으로 로컬 메모리에서만 처리해야 합니다.

## 핵심 사용자 흐름

~~~text
움직이는 메뉴바 캐릭터
        ↓ 클릭
CPU · Memory · Network · Disk 대시보드
        ↓ 카드 선택
상세 지표 · 최근 그래프 · 원인 프로세스
~~~

사용자는 메뉴바에서 상태를 먼저 알아차리고, 원인이 궁금할 때만 대시보드를 엽니다.

## 메뉴바 캐릭터

메뉴바에는 고정된 숫자나 일반 상태 아이콘 대신 ResourceRunner만의 움직이는 캐릭터를 표시합니다.

### CPU 상태와 움직임

| CPU 상태 | 캐릭터 동작 |
| --- | --- |
| 낮음 | 천천히 걷기 |
| 보통 | 가볍게 달리기 |
| 높음 | 빠르게 달리기 |
| 매우 높음 | 전력 질주 |
| 장시간 고부하 | 과부하 상태 표현 |

구체적인 임계치, 지속 시간과 상태 흔들림 방지 규칙은 core-resource-monitoring feature에서 실제 수집값과 함께 확정합니다.

### 보조 자원 표현

| 자원 | 표현 방향 |
| --- | --- |
| CPU | 움직임 속도 |
| Memory Pressure | 캐릭터 상태 변화 |
| Swap 급증 | 무거운 짐이나 지친 동작 |
| Disk I/O | 발밑 효과 또는 끌리는 동작 |
| Network | 작은 신호나 이동 효과 |

여러 상태가 동시에 발생하면 다음 우선순위를 기본으로 사용합니다.

~~~text
Memory Critical
→ Memory Warning
→ CPU 장기 고부하
→ Disk Busy
→ Network Busy
→ Normal
~~~

Disk와 Network 효과는 핵심 상태를 가리거나 메뉴바 공간을 과도하게 사용하지 않아야 합니다.

### 애니메이션 정책

- 평상시에는 2~6 FPS를 사용합니다.
- 높은 부하에서는 8~10 FPS까지 높일 수 있습니다.
- 최대 FPS는 12로 제한합니다.
- 메뉴바 항목의 폭과 기준 위치는 프레임이 바뀌어도 흔들리지 않아야 합니다.
- 데이터 수집 주기와 애니메이션 프레임 갱신 주기는 서로 독립적이어야 합니다.
- 동작 줄이기가 활성화되면 같은 상태를 정적인 표현으로 제공합니다.
- 사용자는 설정에서 애니메이션을 완전히 끌 수 있어야 합니다.
- 팝오버를 열고 닫아도 메뉴바 상태 표현이 불필요하게 중단되지 않아야 합니다.

캐릭터 콘셉트와 자산은 기존 제품과 구별되는 독자적인 디자인으로 확정해야 합니다.

## 대시보드

메뉴바 캐릭터를 클릭하면 CPU, Memory, Network와 Disk 카드가 포함된 팝오버 대시보드가 열립니다.

### 공통 정보 구조

대시보드 상단에는 전체 시스템 상태와 그래프 시간 범위를 표시합니다. 각 카드는 다음 원칙을 공유합니다.

- 기본 상태: 현재값, 최근 그래프와 핵심 원인 또는 보조 정보
- 설명: 지표의 의미와 보조 정보를 Hover로 제공 가능
- 선택: 카드를 선택하면 상세 지표와 추가 원인 정보를 고정된 영역에 표시
- 복귀: 선택한 카드를 다시 선택하거나 명시적인 동작으로 요약 상태로 복귀
- 실패 격리: 한 카드의 수집 실패가 나머지 카드의 사용을 막지 않음
- 데이터 부족: 앱 시작 직후에는 존재하지 않는 과거 데이터를 만들지 않고 수집 중 상태를 표시
- 레이아웃 안정성: 숫자와 순위가 바뀌어도 카드 크기와 정렬이 불필요하게 흔들리지 않음

중요한 분석 정보는 Hover에만 의존하지 않습니다. Hover는 설명을 보조하고, 실제 상세 정보는 선택 후 유지되는 영역에 제공합니다.

### 접근성

- 핵심 사용자 흐름을 키보드로 탐색할 수 있어야 합니다.
- 카드, 현재 상태와 주요 수치에 의미 있는 VoiceOver 레이블을 제공해야 합니다.
- 색상만으로 정상, 경고와 위험을 구분하지 않아야 합니다.
- 동작 줄이기와 애니메이션 비활성화에서도 같은 상태 정보를 확인할 수 있어야 합니다.

## CPU

### 기본 카드

CPU 카드에는 다음 정보를 바로 표시합니다.

- 전체 CPU 사용률
- 최근 1분·5분·10분 중 선택된 범위의 사용량 그래프
- User와 System 비율
- 최근 짧은 구간을 기준으로 안정화한 CPU 사용량 TOP 5

프로세스 CPU 사용률은 여러 코어를 사용하면 100%를 초과할 수 있습니다. 시스템 전체 CPU와 프로세스 CPU의 단위 의미를 UI에서 혼동하지 않도록 구분해야 합니다.

### 상세 정보

- 전체 CPU 사용률
- User, System과 Idle
- 논리 코어별 사용률
- Load Average
- 현재값과 최근 평균 비교
- 프로세스별 CPU 사용률
- 프로세스 스레드 수
- 가능한 경우 Apple Silicon 네이티브 또는 Rosetta 실행 여부
- 앱 단위와 하위 프로세스 단위 보기

### TOP 5 정책

- 순간값만 사용하지 않고 최근 2~3개 CPU 샘플의 평균으로 순위를 안정화합니다.
- 기본 카드에서는 앱 단위 집계를 우선합니다.
- 상세 화면에서는 하위 프로세스를 확인할 수 있어야 합니다.
- Chrome, Electron 앱과 IDE처럼 여러 프로세스로 구성된 앱은 확인 가능한 범위에서 하나의 앱으로 묶습니다.
- 앱으로 묶을 수 없는 명령행 또는 시스템 프로세스는 실행 파일 이름이나 확인 가능한 소유 관계를 기준으로 표시합니다.
- 종료된 프로세스, 접근할 수 없는 프로세스와 PID 재사용 때문에 잘못된 항목이 남아서는 안 됩니다.

구체적인 앱 집계와 프로세스 식별 규칙은 design.md와 core-resource-monitoring feature에서 확정합니다.

## Memory

macOS 메모리는 단순 사용률보다 Memory Pressure와 Swap 상태를 중심으로 설명합니다.

### 기본 카드

- 전체 물리 메모리
- 현재 사용 중 메모리
- Memory Pressure
- Swap 사용량
- 최근 Swap 변화량
- 현재 메모리 사용량 기준 TOP 5

### 상세 정보

- Physical Memory
- App Memory
- Wired Memory
- Compressed Memory
- Cached Files
- Swap Used
- 최근 Swap 증가량
- 프로세스별 Physical Footprint
- 가능한 경우 Resident Memory 보조 정보
- 현재 메모리 사용량 순위
- 최근 1분·10분 메모리 증가량 순위

현재 메모리를 많이 사용하는 앱과 최근 빠르게 증가한 앱을 구분합니다.

~~~text
현재 메모리 사용량
Docker Desktop                  7.8 GB

최근 10분 증가량
Claude                         +1.4 GB
~~~

기본 카드에는 현재 메모리 TOP 5를 표시하고, 상세 화면에는 현재 사용량과 최근 증가량을 별도 순위로 제공합니다. CPU와 Memory의 앱 단위 집계는 같은 기준을 사용해야 합니다.

## Network

### 기본 카드

- 현재 다운로드 속도
- 현재 업로드 속도
- 최근 1분·5분·10분 송수신 그래프
- 현재 활성 인터페이스
- Wi-Fi, Ethernet과 VPN 구분

### 상세 정보

- 인터페이스별 RX와 TX
- IPv4와 IPv6 주소
- 누적 송수신량
- 인터페이스 상태
- 가능한 경우 연결 속도
- 복수 인터페이스 사용 상태

인터페이스 전환과 연결 없음 상태를 명확히 표현해야 합니다. VPN 환경에서 사용자에게 어떤 인터페이스와 합계를 보여주는지 일관된 정책이 필요합니다.

프로세스별 네트워크 사용량, 원격 호스트, 포트별 통계, 패킷 캡처와 Network Extension은 1.0 범위에서 제외합니다.

## Disk

Disk 정보는 저장 공간과 실시간 입출력을 구분해서 표시합니다.

### 기본 카드

- 현재 읽기 속도
- 현재 쓰기 속도
- 최근 1분·5분·10분 입출력 그래프
- 시스템 볼륨 전체 용량
- 사용 가능한 공간

### 상세 정보

- 볼륨별 전체, 사용 중과 사용 가능한 공간
- 장치별 읽기·쓰기 속도
- 누적 읽기·쓰기 크기
- 가능한 경우 IOPS
- 외장 디스크 상태
- 공개 API와 권한 범위에서 가능한 프로세스별 Disk I/O 후보

저장 공간은 초 단위로 바뀌지 않으므로 CPU, Network와 실시간 Disk I/O보다 느린 주기로 갱신합니다. 프로세스별 합계와 장치 전체 합계가 다를 수 있음을 오해 없이 표현해야 합니다.

## 최근 그래프와 데이터 보관

| 항목 | 1.0 기본값 |
| --- | --- |
| 그래프 시간 범위 | 최근 10분 |
| 선택 가능 범위 | 1분, 5분, 10분 |
| 기본 전체 지표 주기 | 대시보드 열림 1초 |
| 저장 위치 | 앱 메모리 |
| 앱 시작 직후 | 실제로 수집된 구간만 표시 |
| 앱 재시작 시 | 초기화 |
| 장기 이력 저장 | 지원하지 않음 |

앱 시작 직후에는 현재값으로 존재하지 않는 과거를 채우지 않습니다.

~~~text
최근 10분
데이터 수집 중 · 00:42 / 10:00
~~~

앱 재시작 후 그래프 복원, 최근 1시간·24시간 보기와 날짜별 통계는 1.0 이후 후보입니다.

## 설정

사용자는 내부 수집 타이머를 각각 조절하지 않고 제품 수준의 간단한 설정을 사용합니다.

### 일반

- 로그인 시 자동 실행
- 팝오버 자동 닫기
- 앱 업데이트 확인
- 설정 초기화

업데이트 확인 항목은 실제 배포·업데이트 방식을 결정한 뒤 제공 여부를 확정합니다.

### 표시

- CPU 카드 표시
- Memory 카드 표시
- Network 카드 표시
- Disk 카드 표시
- CPU·Memory TOP 5 표시 여부
- 시스템 프로세스 포함 여부
- 그래프 시간 범위

### 갱신

- 빠름
- 기본
- 절전
- 매우 절전
- 팝오버가 닫혔을 때 자동 감속
- 저전력 모드에서 자동 감속
- 화면 잠금 시 수집 중지 또는 최소화

### 애니메이션

- 애니메이션 활성화
- 캐릭터 선택
- 최대 FPS
- Memory Pressure 효과
- Disk 효과
- Network 효과
- 동작 줄이기 자동 대응

설정 변경은 가능한 범위에서 즉시 반영하고 앱 재시작 후에도 유지해야 합니다. 지원하지 않는 조합을 만들 수 없어야 하며 기본값 복원을 제공해야 합니다.

## 로그인 시 자동 실행

- 메인 ResourceRunner 앱만 macOS 로그인 항목으로 등록합니다.
- 별도 Helper, LaunchDaemon과 LaunchAgent 파일 직접 설치를 사용하지 않습니다.
- 관리자 권한을 요구하지 않습니다.
- 사용자는 앱 설정과 macOS 시스템 설정에서 등록 상태를 확인할 수 있어야 합니다.
- 등록 실패와 시스템 상태 불일치를 사용자에게 설명할 수 있어야 합니다.

## 데이터와 개인정보

ResourceRunner 1.0은 다음 정책을 따릅니다.

- 사용자 계정을 두지 않습니다.
- 광고와 텔레메트리를 두지 않습니다.
- 원격 서버를 사용하지 않습니다.
- 수집 데이터를 외부로 전송하지 않습니다.
- 프로세스 정보는 로컬에서만 처리합니다.
- 최근 그래프와 TOP 5 계산 결과는 메모리에만 보관합니다.
- 사용자 설정은 macOS 기본 설정 저장소에 보관할 수 있습니다.
- 로그인 시 실행 상태는 macOS 로그인 항목 상태를 사용합니다.
- 장기 통계와 재시작 후 그래프 복원은 제공하지 않습니다.
- 관리자 권한과 별도 Helper를 요구하지 않습니다.

## 1.0 상세 요구사항

ResourceRunner 1.0은 다음 사용자 가치를 함께 제공해야 합니다.

- 움직이는 메뉴바 캐릭터
- CPU 기반 움직임 속도
- Memory Pressure 상태 표현
- 정적 아이콘, 애니메이션 끄기와 동작 줄이기
- CPU·Memory·Network·Disk 카드
- 최근 1분·5분·10분 그래프
- CPU TOP 5
- Memory 현재 사용량과 최근 증가량 TOP 5
- 앱 단위 프로세스 집계
- 카드 선택 상세 정보
- 갱신 속도와 그래프 범위 설정
- 대시보드가 닫혔을 때 자동 감속
- 로그인 시 자동 실행
- Collector별 독립 실패 상태
- 키보드 탐색과 VoiceOver
- 별도 Helper와 관리자 권한 없음
- 장기 통계 저장과 외부 데이터 전송 없음

출시 순서와 품질 관문은 ROADMAP.md를 따릅니다.
