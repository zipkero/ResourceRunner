# 대시보드 시각 정리 명세

## 1. 범위

이미 동작하는 CPU·Memory 카드와 두 상세 팝업이 **같은 값을 어떤 시각 규칙으로 그리는지**를 다룹니다.

표시하는 값·항목·정원·계산·수집은 그대로 두고, 타이포 계층·값 정렬·여백 리듬·표면·색·상시 chrome만 다시 정합니다.
상세 팝업의 내부 시각도 이 범위에 들어갑니다 — 팝업이 카드 옆 별도 팝오버라는 구조는 유지하고 그 안의 배치와 위계를 정리합니다.

### 관찰된 출발점

사용자가 실행 중인 앱을 보고 「좀 더 디자인을 깔끔하게 하고 싶은데.. iStats Menus나 CleanMyMac처럼」이라고 요청했습니다.

코드에서 확인한 출발점은 일곱 가지입니다.

- `ResourceRunner/DashboardView.swift`에서 `.caption`·`.caption2`가 27번, 그보다 큰 글꼴은 3번뿐입니다.
  CPU 전체 사용률(`:157`)과 범례·순위 행·캡션이 모두 같은 크기라 초점이 없습니다.
- 카드 배경이 `RoundedRectangle(cornerRadius: 8).fill(.quaternary)`(`:178`, `:341`)입니다.
  팝오버 자체가 이미 재질인데 그 위에 불투명 회색을 얹어 층이 겹칩니다.
- 카드 하나가 9~10줄입니다 — 제목·요약 2줄·그래프·순위 5줄·캡션·단축키 줄.
- `⌘1 선택·복귀` 줄(`:172`, `:335`)이 수집 상태와 무관하게 상시 노출됩니다.
- 색이 여섯 값·네 색조입니다 — CPU 2색과 Memory 구성 4색(`DashboardColorPalette.swift:54-57`)이
  모두 채도 높은 값이라 280pt 폭 안에서 서로 경쟁합니다.
- 여백이 2·4·6·8·16pt로 자리마다 섞여 있어 줄 묶음이 시각적으로 나뉘지 않습니다.
- 순위·목록·범례의 수치가 모두 왼쪽 흐름 안에 있어 값끼리 세로로 비교되지 않습니다.

**확정된 방향은 iStats Menus 계기판형입니다**(2026-09-03 사용자 선택).
정보 밀도는 지금 수준을 유지하고 계기판처럼 정렬합니다 — 값 우측 정렬과 폭 고정 숫자,
카드 사이 구분과 불투명 채움 제거, 상시 단축키 줄 제거, 색조 수 축소.

2026-09-03 사용자 결정 세 건이 범위를 좁혔습니다.

- 논리 코어 격자는 CPU 상세에 그대로 둡니다. 카드로 올리지 않습니다.
- 카드의 순위 자리는 5줄 고정을 유지합니다.
- 최상단 「ResourceRunner」 제목 줄은 없애고 그 높이를 카드가 씁니다.

2026-09-04 사용자 결정 두 건이 색과 상세 팝업 구분 수단을 확정했습니다.

- Memory 네 구간은 한 색조의 네 단계로 좁히지 않고 **두 색조를 쓰고 각 색조 안에서 두 단계**로 나눕니다.
- 상세 팝업의 섹션 경계는 **여백과 머리글 위계만**으로 만들고 구분선을 쓰지 않습니다.

사용자가 상세 팝업에 대해 덧붙인 확인이 하나 있습니다 —
팝업이 카드 옆에 뜨는 구조 자체는 유지하되 그 내부 디자인도 함께 손봐야 한다는 것입니다.

색 결정의 배경으로 계산해 둔 값이 있습니다(추정이며 검증기 실행 결과가 아닙니다).
배경을 라이트 `#ECECEC`(L\*93.4)·다크 `#2E2E2E`(L\*18.9)로 근사하면
배경 대비 3:1을 넘기는 범위가 라이트에서 L\* ≤ 56.7, 다크에서 L\* ≥ 49.7입니다.
현재 네 색은 색조로 구분되어 인접쌍 ΔL\*가 라이트 9.3/3.9/8.3, 다크 1.9/3.8/3.1이고,
라이트에서 세 구간(Wired 2.71:1, Compressed 2.38:1, Cached 1.83:1)이 3:1에 미달해 relief 조건에 의존합니다.
한 색조 네 단계로도 각 모드 램프를 따로 잡으면 인접쌍 ΔL\* 11과 3:1 통과를 함께 얻을 수 있다는 계산이 나왔지만,
사용자는 색조 차가 명도 차를 보태 여유가 더 큰 두 색조 방향을 택했습니다.
두 색조 × 각 두 단계는 색조당 단계가 둘뿐이라 같은 범위 안에서 인접쌍 ΔL\*를 20 이상으로 벌릴 수 있습니다.

검토했으나 접은 방향이 셋입니다.

- CleanMyMac 초점형(리소스당 큰 수치 하나 + 링, 순위·범례는 상세로 내림)은 접었습니다.
  가장 깔끔해지지만 한눈에 보이는 정보량이 줄어, 「메뉴바에서 원인까지」라는 제품 방향과 어긋납니다.
- 구조를 그대로 두고 스타일 토큰만 정리하는 방향도 접었습니다.
  고정 슬롯과 상시 chrome이 그대로 남으면 개선 폭이 사용자가 지적한 수준에 닿지 않습니다.
- Memory 구성을 세 구간 + 「기타」로 묶어 색 단계를 줄이는 방향도 접었습니다.
  `docs/product.md` 「Memory > 기본 카드」가 네 항목을 명시하고
  resource-visualization `SPEC §5.3`이 네 구간 표시를 완료 조건으로 닫아 둔 상태라,
  색 하나 때문에 앞선 feature의 완료 조건을 되돌리는 셈입니다.

## 2. 목표

팝오버를 열었을 때 **눈이 먼저 갈 자리가 정해지고, 같은 종류의 값이 같은 규칙으로 놓여 훑어 읽을 수 있게** 합니다.

- 리소스마다 초점 수치 하나가 나머지보다 확실히 크게 읽혀, 카드를 다 읽지 않고도 지금 상태를 압니다.
- 수치가 같은 세로선에 맞춰 놓여 값끼리 크기를 비교할 수 있습니다. 지금은 이름 길이에 따라 값 위치가 매 행 달라집니다.
- 카드가 회색 블록이 아니라 팝오버 표면 위의 구획으로 읽힙니다.
- 정보가 아닌 표시(상시 단축키 줄, 앱 자신의 이름)가 사라지고 그 높이를 값이 씁니다.
- 상세 팝업 안에서 섹션의 시작과 끝이 보여, 400×480 안에 쌓인 내용이 한 덩어리로 읽히지 않습니다.

## 3. 제약

- 표시하는 값·항목·정원·계산·수집 주기를 바꾸지 않습니다.
  이 feature는 표시 계층 안에서 끝나며, 카드와 상세가 지금 보여주는 항목 집합은 그대로입니다.
- 본체 팝오버 폭은 320pt를 넘지 않습니다(현재 280pt).
- CPU·Memory 카드 하나의 높이가 변경 전보다 커지지 않습니다.
  M3에서 카드가 넷으로 늘어나므로 이 feature가 세로 예산을 먹으면 그때 팝오버가 화면을 넘습니다.
- 상세 팝업은 카드 옆에 앵커된 별도 팝오버, 고정 크기, 내부 세로 스크롤 하나라는 구조를 유지합니다.
  고정 크기의 **값**은 새 표현에 맞춰 다시 확정할 수 있습니다.
- 레이아웃 안정성을 유지합니다.
  수집 중·정상·실패·중지 사이를 오가도, 상세를 열고 닫아도, 앱 행을 펼치고 접어도 크기와 위치가 흔들리지 않습니다.
  아직 값이 없는 그래프·순위 자리는 비워 두지 않고 같은 높이의 자리표시로 채웁니다.
- 카드 순위 자리는 TOP 5 정원의 줄 수를 항상 차지합니다(2026-09-03 결정).
- 색만으로 정보를 전달하지 않습니다.
  계열·구간은 색 외의 수단(라벨·기호·수치·채움 밀도·경계선 모양)으로도 구분됩니다.
- 구분에 쓰는 색조를 현재 넷에서 셋 이하로 줄입니다.
  CPU의 User·System은 한 색조의 두 단계로 표시합니다.
  Memory의 네 구간은 두 색조를 쓰고 각 색조 안에서 두 단계로 나눕니다 —
  App·Wired가 한 색조, Compressed·Cached가 다른 색조입니다(2026-09-04 결정).
- 라이트와 다크 램프는 각각 따로 확정합니다. 한쪽 값에서 반전으로 유도하지 않습니다.
- 새 색 집합은 인접쌍 색맹 시뮬레이션 ΔE ≥ 8과 배경 대비 3:1 이상을 함께 만족하는 것을 목표로 하고,
  그 결과로 스와치 옆 이름이 없으면 색 선택이 성립하지 않는 relief 조건 의존을 없앱니다.
  3:1을 만족하지 못하는 구간이 남으면 그 구간에 한해 relief 조건을 유지합니다.
  범례에 항목 이름을 두는 것 자체는 relief 조건과 별개로 위의 색 비의존 제약 때문에 그대로 유지합니다.
- 「사용 중」과 구성 항목 합계는 정의가 다른 별개 지표이며, 화면에서 같은 값처럼 보이게 두지 않습니다.
- 상시 단축키 줄을 지워도 키보드 선택·복귀는 그대로 동작해야 합니다
  (core-resource-monitoring `SPEC §5.13`). 키보드 탐색 설정이 꺼진 기본 환경에서도 성립해야 합니다.
- 변경 전에 접근성 계층에서 이름·값으로 도달했던 요소는 변경 후에도 같은 범위로 도달합니다.
  `docs/design.md`의 `AXLabel`·`AXValue` 관례를 보존하거나, 바꾼다면 그 관례에 기대는 UI 테스트 경계를 함께 조정합니다.
- 균등 분할 영역의 폭 잔차가 상위 레이아웃으로 새지 않는 구조를 유지합니다(`docs/design.md` §균등 분할 폭 잔차).
- 동작 줄이기와 애니메이션 끄기에서도 같은 정보를 확인할 수 있어야 하며, 새 표현이 애니메이션을 전제하지 않습니다.
- 이 앱 자체가 리소스 모니터이므로, 새 표현이 갱신 주기마다 지속적인 CPU 부하를 더하지 않습니다.
- App Sandbox를 유지하고 새 entitlement를 추가하지 않습니다.

## 4. 제외 범위

- 표시 항목의 추가·삭제와 자리 이동.
  논리 코어 격자를 카드로 올리는 것을 포함합니다(2026-09-03 결정으로 상세에 유지).
- 카드 순위 정원 변경(2026-09-03 결정으로 5줄 고정 유지).
- Memory 구성 구간 수 변경. 네 구간을 묶거나 나누지 않습니다(2026-09-04 결정).
- 상세 팝업의 섹션 경계를 위한 구분선·배경·테두리(2026-09-04 결정).
  섹션 경계는 여백과 머리글 위계로만 만듭니다.
  본체 팝오버의 카드 사이 구분(§5.3)은 이 결정의 대상이 아닙니다 — 카드는 선택할 수 있는 독립 단위이고,
  상세 섹션은 한 카드 안의 내용 묶음이라 층위가 다릅니다.
- 값의 정의·계산·수집 주기·이력 링 용량·평활화 창 변경.
- Network·Disk 카드의 시각 표현. M3 extended-resource-monitoring 소관입니다.
- 표시 항목·색·순위 정원·그래프 시간 범위를 사용자가 고르는 설정. M4 소관입니다.
- 상세 팝업을 별도 창으로 승격하거나 본체 안 인라인 확장으로 바꾸는 구조 변경.
- 하위 프로세스 행을 구분하기 위한 구분선·배경·테두리
  (detail-popover-readability 2026-08-31 결정을 그대로 유지, 구분은 들여쓰기와 간격).
- 메뉴바 캐릭터 자산·아이콘·애니메이션.
- 프로세스 종료 같은 조작 기능.
- 라이트·다크 외의 테마와 사용자 색 선택.

## 5. 완료 조건

1. 카드마다 초점 수치 하나 — CPU는 전체 사용률, Memory는 사용 중/전체 — 가 같은 카드의 다른 텍스트보다 큰 글꼴로 표시되고,
   팝오버를 연 화면에서 그 수치가 가장 먼저 읽힙니다.
2. 카드 순위 행, 상세 앱 목록 행, 상세 범례 행의 수치가 각 목록 안에서 오른쪽 끝에 맞춰 정렬되고,
   앱 이름 길이나 자릿수가 달라져도 단위와 소수점 자리가 같은 세로선에 남습니다.
3. 카드에 불투명 회색 채움이 없고, 카드 경계가 팝오버 표면과 구분되면서 두 카드가 서로 구분됩니다.
   이 조건은 이후 `20260912-001-dashboard-visual-language`가 대체했습니다 —
   그 feature가 카드 면을 바탕보다 띄우는 쪽으로 다시 정해
   현재 코드의 카드 표면은 테두리가 아니라 불투명 채움(`DashboardStyle.CardSurface.fillColor`)입니다.
   「카드 경계가 팝오버 표면과 구분되고 두 카드가 서로 구분된다」는 그 채움으로 성립합니다.
4. 카드 안에서 줄 묶음 사이 간격이 묶음 안의 줄 간격보다 크고, 같은 위계의 자리는 같은 간격을 씁니다.
5. `⌘1 선택·복귀`·`⌘2 선택·복귀` 줄과 「ResourceRunner」 제목이 화면에서 사라지고,
   그 높이만큼 카드가 위로 올라옵니다.
   키보드 탐색 설정이 꺼진 기본 환경에서 ⌘1·⌘2로 두 카드를 선택하고 복귀할 수 있으며,
   각 카드의 접근성 이름에서 그 단축키를 확인할 수 있습니다.
6. CPU의 User·System 두 계열이 한 색조의 두 단계로, Memory 구성 네 구간이 두 색조 각 두 단계로 표시되고,
   색을 지운 화면에서도 어느 계열·구간인지 구분됩니다.
   구분에 쓰는 색조가 셋 이하로 줄고, 새 색 집합이 §3의 색 기준을 통과한 결과가 확인됩니다.
7. CPU 상세와 Memory 상세를 열면 섹션의 경계가 여백과 머리글 위계만으로 보여 어디까지가 한 섹션인지 알 수 있고,
   섹션 머리글이 그 안의 값보다 낮은 위계로 읽히면서도 본문과 구분됩니다.
   섹션 경계에 구분선·배경·테두리를 쓰지 않으며, 하위 프로세스 행의 소속 구분도 들여쓰기와 간격으로만 이뤄집니다.
8. 상세 팝업의 수치가 §5.2와 같은 정렬 규칙을 따르고, 코어 격자의 칸 안 수치도 칸마다 같은 자리에서 읽힙니다.
9. 본체 팝오버와 두 상세 팝업의 크기가 새 표현에 맞춰 다시 확정되고,
   수집 중·정상·실패·중지 사이를 오가도, 상세를 열고 닫아도, 앱 행을 펼치고 접어도 그 크기와 카드 위치가 변하지 않습니다.
10. CPU·Memory 카드 하나의 높이가 변경 전보다 크지 않습니다.
    이 조건은 이후 `20260906-001-graph-legibility-and-color`와 `20260912-001-dashboard-visual-language`가 대체했습니다 —
    앞 feature의 `spec.md` §제약이 「카드와 본체 팝오버가 커지는 것은 허용하되,
    M3에서 카드가 넷이 된 상태의 세로 예산을 함께 계산해 화면 안에 들어가는 것이 확인되어야 합니다」로 다시 정했습니다.
    현재 카드 높이는 CPU 329pt·Memory 224pt로 이 조건이 상한으로 삼던 243pt·181pt를 넘습니다.
11. 변경 전에 접근성 계층에서 이름 또는 값으로 도달했던 요소가 변경 후에도 같은 범위로 도달합니다 —
    카드의 상태와 주요 수치, 상세 팝업의 내용, 코어 칸의 번호와 사용률, 하위 프로세스 행의 소속 앱과 값입니다.
12. 동작 줄이기와 애니메이션 끄기 설정에서 위 표시가 모두 같은 정보를 전달합니다.
13. 팝오버를 열어 둔 채 관찰한 앱 자신의 CPU 사용량이 변경 전과 비교해 지속적으로 상승하지 않습니다.
14. 논리 코어 14개인 기기에서 코어 격자 전체가 CPU 상세의 첫 화면 스크롤 없이 들어오던 상태가 유지되고,
    코어 수가 그보다 적거나 많아도 배치가 코어 수를 따라갑니다.
