# CPU·Memory 핵심 리소스 모니터링 명세

## 범위

이 feature는 실제 CPU와 Memory 데이터를 수집해 대시보드 팝오버의 CPU 카드와 Memory 카드로 설명합니다.
시스템 전체 지표, 앱 단위로 묶은 프로세스 순위, 최근 10분 그래프와 카드 상세 정보를 포함합니다.
M1이 자리표시 샘플로 돌리던 수집 기반에 실제 Collector를 연결하고,
실제 CPU 값으로 메뉴바 상태를 판정하는 규칙도 여기서 확정합니다.

CPU와 Memory만으로 현재 문제와 주요 원인을 파악할 수 있는 내부 알파를 이 feature의 경계로 삼습니다.

캐릭터 자산 제작과 메뉴바 애니메이션은 이 feature에서 다루지 않고 M2 안의 후속 feature로 분리합니다.
다만 실제 CPU 값에서 다섯 표시 상태를 판정하는 규칙은 이 feature가 정합니다.
판정 규칙이 없으면 후속 feature가 그릴 대상이 정해지지 않고, 실제 값에 붙은 판정을 여기서 검증할 수 있기 때문입니다.
M1이 만든 메뉴바 접근성 이름이 그 판정 결과를 그대로 받습니다.

### 확정한 판단

`/spec-init` 전에 정한 내용이며 이 feature의 전제입니다.

- App Sandbox를 유지합니다. 프로세스별 Physical Footprint를 포기하고 Resident Memory로 메모리 사용을 설명합니다.
- CPU 사용률은 논리 코어를 합산하는 Activity Monitor 관례를 따릅니다.
- Memory Pressure는 문서화된 3단계 신호를 그대로 쓰고 연속 곡선을 재현하지 않습니다.
- 최근 그래프는 샘플의 실제 시각을 기준으로 그리고 수집하지 않은 구간을 비워 둡니다.
- 화면 잠금에 더해 디스플레이 슬립과 빠른 사용자 전환에서도 수집을 중지합니다.

`docs/product.md`의 Memory 상세는 프로세스별 Physical Footprint를 주 지표로,
Resident Memory를 「가능한 경우」의 보조 정보로 적고 있습니다.
Sandbox 유지 결정으로 둘의 위치가 바뀌었으므로 이 feature는 Resident Memory를 주 지표로 삼습니다.

### SPEC 재작성으로 바뀐 것

이 SPEC은 카드 상세를 「하단 고정 영역」에 두는 전제로 한 번 완성돼 구현·검증까지 마쳤습니다.
이후 `docs/product.md` §공통 정보 구조가 두 곳 개정되어 그 전제가 바뀌었고, 그래서 다시 씁니다.

- 상세 표시 방식이 「고정된 영역」에서 「그 카드 옆에 붙는 팝업」으로 바뀌었습니다.
  대시보드 본체는 상세를 위한 자리를 예약하지 않습니다.
- 레이아웃 안정성 원칙이 값 변화뿐 아니라 상태 전이(수집 중·정상·실패·중지)까지 덮도록 확장됐습니다.
  팝오버를 연 직후 첫 수집이 도착하면 그래프와 순위가 없던 자리에 생기면서
  카드가 부풀어 아래 내용을 밀어내는 것이 관찰됐고, 기존 문구가 "숫자와 순위가 바뀌어도"라
  값 변화만 덮고 있어 이 경우가 빠져 있었습니다.

카드 옆 팝업이 이 앱의 실행 환경에서 성립하는지는 SPEC을 고치기 전에 확인했습니다.
메뉴바 팝오버가 `.transient`라 자식 팝업이 부모를 닫을 수 있다는 우려가 있었으나,
카드 클릭은 부모 창 안에서 일어나 닫힘 계기가 아니며 두 팝오버가 공존했습니다.
자식 팝업이 접근성 계층에서 부모 팝오버의 하위 노드로 들어가 그 내용에도 도달됐습니다.

검토했으나 접은 방식은 하나입니다 — 팝오버 본체의 폭을 넓혀 오른쪽 절반에 상세를 붙이는 분할 배치입니다.
`NSPopover`가 앵커 기준으로 중앙 정렬이라 콘텐츠 폭이 바뀌면 카드 열이 좌우로 밀려
레이아웃 안정성 요구와 어긋납니다.

## 목표

- 사용자가 팝오버를 열어 CPU와 Memory의 현재 상태, 최근 10분의 흐름과 그 원인이 되는 앱을
  한 화면에서 확인할 수 있게 합니다.
- 현재 많이 쓰는 앱과 최근 빠르게 늘어난 앱을 구분해, 무엇이 지금 문제인지 판단할 수 있게 합니다.
- 메뉴바 표시 상태가 주입값이 아니라 실제 CPU 부하를 따라가게 하고,
  값이 경계 근처에서 흔들려도 표시가 요동치지 않게 합니다.
- 프로세스가 끝나거나 접근이 막히거나 PID가 재사용되어도 순위와 이력이 틀어지지 않게 합니다.
- 한 지표의 수집이 실패해도 나머지 카드와 메뉴바는 계속 쓸 수 있게 합니다.
- 값이 도착하거나 상태가 바뀌는 순간에 화면이 흔들리지 않게 해,
  사용자가 읽던 자리를 다시 찾지 않아도 되게 합니다.

## 제약

- macOS 26.5 이상 Apple silicon에서 동작하고, App Sandbox를 유지하며 배포 가능한 앱 실행 파일은 arm64만 포함합니다.
- 별도 Helper, 관리자 권한, 시스템 확장과 추가 상주 프로세스를 요구하지 않습니다.
- root 소유 프로세스의 CPU 시간과 메모리는 읽을 수 없습니다.
  전체 프로세스의 상당수가 여기 해당하므로 TOP 5는 사실상 사용자 소유 프로세스로 한정됩니다.
  읽지 못한 프로세스의 사용량을 추정해 채우지 않으며, 목록이 시스템 프로세스를 담지 않는다는 사실을 사용자에게 알립니다.
- 프로세스별 Physical Footprint를 사용할 수 없습니다. 프로세스 메모리는 Resident Memory로 표현합니다.
- Memory Pressure는 정상·경고·위험 3단계로만 표현하고 연속적인 압력 수치를 만들지 않습니다.
- 프로세스 CPU 사용률은 여러 코어를 쓰면 100%를 넘습니다.
  시스템 전체 CPU와 프로세스 CPU의 단위 의미가 화면에서 구분되어야 합니다.
- 최근 그래프의 시간 범위는 10분 하나로 고정합니다.
- 수집한 데이터는 메모리에만 유지하며 외부 전송, 영구 저장과 앱 재시작 후 복원을 하지 않습니다.
- 존재하지 않는 과거 데이터를 만들지 않습니다. 수집하지 않은 구간은 그래프에서 비워 둡니다.
- 프로세스 조사 주기는 시스템 전체 지표 수집 주기와 분리하고,
  팝오버가 닫히면 감속하며 화면을 볼 수 없는 상태에서는 중지합니다.
- 카드 상세는 그 카드 옆에 붙는 팝업으로 열립니다.
  대시보드 본체는 상세를 위한 자리를 예약하지 않으며, 상세를 열고 닫아도 카드가 움직이지 않습니다.
- 카드 높이는 수집 상태와 무관하게 일정합니다.
  아직 값이 없는 그래프와 순위 자리는 비워 두지 않고 같은 높이의 자리표시로 채웁니다.
  자리표시는 값을 지어내는 것이 아니라 아직 값이 없음을 나타내는 표시입니다.
- 색상만으로 정상·경고·위험을 구분하지 않습니다.
- 카드의 현재 상태와 주요 수치에 접근성 이름을 제공하고, 핵심 흐름을 키보드로 탐색할 수 있어야 합니다.

## 제외 범위

- 캐릭터 콘셉트 확정, 상태별 자산 제작과 메뉴바 애니메이션.
  애니메이션 프레임 일정과 FPS 정책, 저전력·화면 잠금에 따른 감속·정지,
  동작 줄이기에서의 정적 표현도 후속 feature에서 다룹니다.
- Network와 Disk의 수집, 카드와 상세 정보. 이 feature의 대시보드에는 CPU와 Memory 두 카드만 둡니다.
- 그래프 시간 범위 선택(1분·5분·10분)과 사용자 갱신 속도 설정.
- 설정의 영구 저장, 기본값 복원과 로그인 시 자동 실행.
- 시스템 슬립 복귀 후 첫 샘플의 기준점 재설정.
  변화량으로 속도를 계산하는 지표가 없는 동안에는 필요하지 않습니다.
- 상세 팝업을 카드와 독립적으로 고정해 두는 기능. 별도 상세 창은 1.0 이후 후보입니다.
- VoiceOver 실제 낭독 확인, 성능·장기 안정성 관문과 정확성 최종 검증.
- 코드 서명, 공증, 업데이트 전달과 설치 가능한 배포물.

## 완료 조건

1. 팝오버를 열면 CPU 카드에 전체 CPU 사용률, User와 System 비율, 최근 10분 그래프와
   CPU 사용량 TOP 5가 표시되고, Memory 카드에 전체 물리 메모리, 현재 사용 중 메모리,
   Memory Pressure 단계, Swap 사용량과 최근 변화량, 메모리 사용량 TOP 5가 표시됩니다.
2. 카드를 선택하면 그 카드 옆에 열리는 팝업에 상세 지표가 표시되고,
   다시 선택하면 팝업이 닫히며 요약 상태로 돌아옵니다.
   CPU 상세에는 User·System·Idle, 논리 코어별 사용률, Load Average, 프로세스별 사용률과
   각 프로세스의 Apple silicon 네이티브·Rosetta 실행 여부가,
   Memory 상세에는 App·Wired·Compressed·Cached, Swap 사용량과 증가량,
   현재 사용량 순위와 최근 증가량 순위가 각각 포함됩니다.
3. CPU와 Memory의 값과 변화 방향이 정해진 비교 절차에서 macOS 시스템 도구와 일관됩니다.
   프로세스 CPU 사용률은 코어를 합산한 값으로 표시되어 여러 코어를 쓰는 프로세스가 100%를 넘습니다.
4. 실제 CPU 부하가 오르내릴 때 메뉴바 항목의 접근성 이름이 다섯 상태를 따라 바뀌고,
   값이 상태 경계 근처에서 흔들려도 표시 상태가 반복해서 뒤집히지 않습니다.
   장시간 고부하는 짧은 순간 부하와 구분됩니다.
5. Memory Pressure가 경고나 위험으로 바뀌면 Memory 카드가 색상 외의 수단으로도 그 단계를 나타내고,
   정상으로 돌아오면 원래 표시로 복귀합니다.
6. TOP 5는 앱 단위로 묶여 표시되고, 여러 프로세스로 구성된 앱이 하나의 항목으로 나타납니다.
   상세에서 그 앱의 하위 프로세스를 확인할 수 있습니다.
   순간값이 아니라 최근 여러 샘플을 반영해 순위가 매 갱신마다 요동치지 않습니다.
   목록에 시스템 프로세스가 포함되지 않는다는 사실이 카드에서 확인되며,
   읽지 못한 프로세스의 사용량이 추정값으로 채워지지 않습니다.
7. 프로세스가 종료되거나 접근에 실패하거나 PID가 재사용되어도
   사라진 프로세스가 순위에 남거나 다른 프로세스의 이력을 이어받는 일이 없습니다.
8. 현재 메모리를 많이 쓰는 앱과 최근 10분 사이 메모리가 많이 늘어난 앱이 서로 구분되어 제공됩니다.
9. 팝오버를 열면 마지막으로 수집된 값이 즉시 표시되고, 최신 값은 그 뒤 갱신으로 반영됩니다.
   여는 순간 빈 화면이나 로딩 상태가 먼저 나타나지 않습니다.
10. CPU와 Memory 중 한쪽의 수집이 실패해도 다른 카드와 메뉴바 표시는 계속 동작하고,
    실패한 카드는 그 사실을 나타냅니다.
11. 앱 시작 직후에는 실제로 수집된 구간만 그래프에 나타나고, 없는 과거가 채워지지 않습니다.
    화면 잠금·디스플레이 슬립·빠른 사용자 전환으로 수집이 중지된 구간은
    그래프에서 시각에 맞는 자리에 빈 구간으로 남으며, 중지 전후 값이 이어 붙지 않습니다.
12. 팝오버 열림·닫힘, 저전력 모드, 화면 잠금, 디스플레이 슬립과 빠른 사용자 전환에 따라
    수집 일정이 바뀌고, 화면을 볼 수 없는 세 상태에서는 새 샘플이 쌓이지 않습니다.
13. 카드의 현재 상태와 주요 수치가 접근성 이름으로 제공되고,
    CPU와 Memory 카드의 선택과 복귀를 키보드로 수행할 수 있습니다.
    상세 팝업의 내용도 접근성 계층에서 도달할 수 있습니다.
14. macOS 26.5 이상 Apple silicon에서 App Sandbox를 유지한 채 위 동작이 성립하고,
